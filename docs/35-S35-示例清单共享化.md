## 一、改动①：示例问题清单共享化

### 1.1 问题

原来两边各自硬编码：

| 位置 | 内容 |
|:---|:---|
| 前端 `app.js` | `const STARTERS = [...]` 6 条 |
| 后端 `app.py` | `WARMUP_QUESTIONS = [...]` 前 6 条 + 9 条额外 |

**风险**：改前端示例问题忘记改后端 → 预热白跑（预热的不是用户会点的）。

### 1.2 方案：一份 JSON，两端读取

新建 `web/data/starters.json`：

```json
{
  "_comment": "前端示例问题 + 后端关键词预热清单（共享数据源）",
  "starters": [
    { "q": "贾宝玉的丫鬟有谁？",   "k": "事实型 · 可检索" },
    { "q": "林黛玉为什么进贾府？", "k": "推理型 · 需结合原文" },
    { "q": "第19回为什么批语最多？", "k": "统计型 · 可验证" },
    { "q": "宝玉和黛玉是什么关系？", "k": "图谱型 · 走知识图谱" },
    { "q": "「千红一窟」有什么隐喻？", "k": "推理型 · 脂批证据" },
    { "q": "前80回一共多少字？",   "k": "事实型 · 精确可答" }
  ],
  "warmup_extra": [
    "宝玉为什么挨打？", "晴雯为什么被撵？", "金钏为什么投井？",
    "黛玉葬花在第几回？", "通灵宝玉上的铭文是什么？", "宝钗扑蝶是怎么回事？",
    "刘姥姥进大观园在哪一回？", "贾宝玉的丫鬟有哪些", "宝玉和黛玉什么关系"
  ]
}
```

### 1.3 前端改造

```javascript
let STARTERS = [ /* 内置兜底 */ ];

async function loadStarters() {
  try {
    const r = await fetch('/data/starters.json?v=' + Date.now());
    if (!r.ok) return;
    const d = await r.json();
    if (Array.isArray(d.starters) && d.starters.length) {
      STARTERS = d.starters;
    }
  } catch (e) {
    console.warn('[starters] 加载失败，用内置值', e);
  }
}

// boot() 里：
await loadStarters();      // 先加载，再渲染界面
await probeBackend();
```

**为什么保留内置兜底**：JSON 404/网络失败时界面不能空白。

### 1.4 后端改造

```python
_STARTERS_PATHS = [
    "/app/starters.json",                                      # 容器内
    "/workspace/web/data/starters.json",                       # 挂载路径
    os.path.join(os.path.dirname(os.path.abspath(__file__)),
                 "..", "web", "data", "starters.json"),        # 本地开发
]

_FALLBACK_WARMUP = [ ... 15 条 ... ]

def _load_warmup_questions():
    """从共享 JSON 读取预热清单；失败则用内置兜底"""
    for p in _STARTERS_PATHS:
        try:
            if not os.path.exists(p):
                continue
            with open(p, encoding="utf-8") as f:
                d = json.load(f)
            qs = [s.get("q") for s in (d.get("starters") or []) if s.get("q")]
            qs += [q for q in (d.get("warmup_extra") or []) if q]
            # 去重保序
            seen, out = set(), []
            for q in qs:
                if q not in seen:
                    seen.add(q); out.append(q)
            if out:
                log(f"  预热清单: 从 {p} 读取 {len(out)} 条")
                return out
        except Exception as e:
            log(f"  读 {p} 失败: {type(e).__name__}")
    log(f"  预热清单: 用内置兜底 {len(_FALLBACK_WARMUP)} 条")
    return list(_FALLBACK_WARMUP)

WARMUP_QUESTIONS = _load_warmup_questions()
```

**三个候选路径**依次尝试，覆盖容器/挂载/本地开发三种环境。

## 二、顺带修的三个数据错误

验证前端时发现三个数字不对，逐一核查修正。

### 2.1 错误①：癸酉本 28 个重复文件

**现象**：`web/data/versions/guiyouben/` 有 **56 个文件**（应为 28 回），
字数从 215,958 虚增到 **431,916**（近一倍）。

**原因**：目录里混着两套命名：

| 文件名 | hui 字段 | 实际回次 |
|:---|:---:|:---|
| `chapter_001.json` | 1 | **第81回** ← 错误残留 |
| `chapter_081.json` | 81 | 第81回 ✅ |

`chapter_001~028.json` 是早期版本按"序号"命名的产物，
`hui` 字段写的是序号（1~28）而内容是第 81~108 回。

**修法**：识别「hui 字段与 huimu 中真实回次不符」的文件，移到 `_stale_backup/`：

```python
for f in sorted(os.listdir(d)):
    dd = json.load(open(fp, encoding="utf-8"))
    m = re.search(r"第(\d+)回", dd.get("huimu", ""))
    real = int(m.group(1)) if m else None
    fno = int(re.search(r"(\d+)", f).group(1))
    if real and real != fno:          # 不符 = 错误残留
        shutil.move(fp, os.path.join(bak, f))
```

**结果**：28 个文件 / 215,958 字（与源语料 223,838 基本吻合）。

### 2.2 错误②：三版本正文总字数

**现象**：前端显示 **167.8 万字**，实际应为 **166.5 万**。

**修法**：两处（`app.js` + `page_home.js`）改为 166.5 万。

| 版本 | 字数 |
|:---|---:|
| 抚琴居 | 587,620 |
| 程高本 | 861,457 |
| 癸酉本 | 215,958 |
| **合计** | **1,665,035 = 166.5 万** |

### 2.3 错误③：图谱边数

**现象**：`manifest.json` 里 `graph_edges=253`，而 `graph.json` 实际有 **673 条边**。

**原因**：S29 重建图谱后 `graph.json` 更新了，但 `manifest.json` 没同步。

**修法**：从 `graph.json` 取真实值写回 manifest：

```python
g = json.load(open("graph.json", encoding="utf-8"))
m["stats_summary"]["graph_nodes"] = len(g["nodes"])   # 350
m["stats_summary"]["graph_edges"] = len(g["edges"])   # 673
```

**修正后**：`graph_nodes=350, graph_edges=673`。

> 注意：350 是**实际入图的节点数**（按度数取前 350 个），
> `n_nodes_total=398` 是三元组里的总人物数（含未入图的孤立点）。

### 关于遗留 #1

若希望改 JSON 后免重建，可以把 `starters.json` 改成**挂载**：

```bash
docker run -v $root\web\data:/app/data ...
```

但当前 `web/data` 目录很大（含所有章节 JSON），全挂载不合适。
可以只挂单个文件：

```bash
docker run -v $root\web\data\starters.json:/app/starters.json:ro ...
```

## 六、教训

三个数据错误有一个共同点：**改了数据源，没同步派生数据**。

| 错误 | 数据源变了 | 派生数据没跟 |
|:---|:---|:---|
| ① 癸酉本重复 | 命名规则改了 | 旧文件没清 |
| ② 总字数 | 目录内容变了 | 硬编码数字没改 |
| ③ 图谱边数 | graph.json 变了 | manifest.json 没跟 |

**建议**：所有派生数字都应该**运行时算**，而不是硬编码进前端。

当前 `166.5 万` 仍是硬编码 —— 更好的做法是从 `/api/manifest` 读 `total_chars` 动态显示。
（本次未改，因为改动面较大）
