# S29 · 图谱共现叠加层（把 MapReduce 接入人物关系图）

> 日期：2026-10-26
> 起因：用户提问「项目里人物关系图的实现和 hadoop 有没有关系？」

---

## 一、先回答原问题：没有关系

排查三处，结论明确：

| 检查项 | 结果 |
|:---|:---|
| 生成脚本 `build_ui_data.py` 是否调 HDFS/HBase | ❌ 无任何 `hdfs` / `happybase` 调用 |
| HDFS 里有无图谱文件 | ❌ `hdfs dfs -find /hlm -name "*graph*"` 无结果 |
| HBase 有无图谱表 | ❌ 只有 5 张表，无 `hlm_kg` |

**边的真实来源**：4 个本地 CSV（开源知识图谱）

| 文件 | 边数 |
|:---|---:|
| `kg-hongloumeng__hlm_triples.csv` | 326 |
| `KGQAHLM__relation.txt` | 170 |
| `DotRC__stone_story_edges.csv` | 156 |
| `The-Dream-of-the-Red-Chamber__triples.csv` | 31 |

**唯一沾边的间接点**：节点权重（大小）用了正文提及次数，而这个统计有 MapReduce 参与 —— 但权重只用于「排序取前 120 节点」，与边无关。

**结论**：边 0% 来自 Hadoop，节点权重间接沾一点。

---

## 二、但矛盾在于：MapReduce 共现数据算了却没用上

项目里同时存在：

```
MapReduce cooccur 作业
  HDFS /hlm/mrout/cooccur  → 10,742 行（逐 chunk）
       ↓ 聚合
  HBase hlm_stats  → 588 对 cooccur|<A>|<B>  cnt
       ↓
  只用在了 RAG 的 L3 检索通道
      ❌ 没用在关系图可视化上
```

于是做了本轮的**叠加层**：让关系图同时展示两套关系数据。

## 三、实现

### 3.1 数据导出

新增 `pipeline/s29_build_cooccur_overlay.py`（在 master 容器内运行）

```python
conn = happybase.Connection("localhost", 9090,
                           table_prefix=b"", table_prefix_separator=b"")
t = conn.table("hlm_stats")

for k, v in t.scan(row_prefix=b"cooccur|"):
    _, a, b = k.decode().split("|")
    cnt = int(v.get(b"s:cnt", b"0").decode() or 0)
    if cnt >= 10:                      # 阈值：太低变蜘蛛网
        pairs.append({"source": a, "target": b, "count": cnt})
```

输出 `web/data/cooccur_overlay.json`（18,674 B）：

```json
{
  "generated_from": "HBase hlm_stats (cooccur|A|B, cf=s:cnt)",
  "upstream": "MapReduce cooccur 作业 /hlm/mrout/cooccur",
  "min_count": 10,
  "n_pairs": 250,
  "edges": [
    {"source": "贾宝玉", "target": "贾母",   "count": 283},
    {"source": "林黛玉", "target": "贾宝玉", "count": 237},
    ...
  ]
}
```

**结果**：250 对（≥10 次），涉及 33 个节点，次数范围 10~283。

// 共现边：红色虚线，透明度随强度递增（0.06 ~ 0.22）
if (coLinks.length) {

## 四、踩的 1 个坑：绘制顺序

### 现象

第一次叠加后，**语义边（灰实线）全部消失**，只剩红色虚线。

### 原因

我把共现边代码插进了语义边的**循环内部**（缩进错位）：

```javascript
for (const l of links) {              // 遍历语义边
  ctx.beginPath();
  ctx.moveTo(a.x, a.y); ctx.lineTo(b.x, b.y);

  // ❌ 错在这里：共现边被插进了循环里
  if (coLinks.length && !dim) {
    ctx.save();
    ctx.strokeStyle = 'rgba(176,58,46,.22)';
    for (const cl of coLinks) {       // 每条语义边都重绘全部共现边
      ...
      ctx.stroke();
    }
    ctx.restore();
  }

  ctx.strokeStyle = 'rgba(180,168,150,.6)';   // 被下面的 stroke 覆盖
  ctx.stroke();
}
```

两个后果：
1. **性能灾难**：253 条语义边 × 250 条共现边 = 63,250 次重绘
2. **样式错乱**：`ctx.strokeStyle` 被共现边的红色覆盖，语义边画出来也是红的

### 修法

把共现边移到循环**外面**，先画共现（底层），再画语义（上层）：

```javascript
// ---- 先画共现边（底层）----
if (coLinks.length) {
  ctx.save();
  ctx.setLineDash([3, 4]);
  for (const cl of coLinks) { ... ctx.stroke(); }
  ctx.restore();
}

// ---- 再画语义边（上层）----
for (const l of links) {
  ctx.beginPath();
  ctx.moveTo(a.x, a.y); ctx.lineTo(b.x, b.y);
  ctx.strokeStyle = dim ? 'rgba(221,210,194,.35)' : 'rgba(180,168,150,.6)';
  ctx.lineWidth = dim ? 0.6 : 1.1;
  ctx.stroke();
}
```

> **教训**：Canvas 绘制代码缩进错了很难看出来 —— 语法正确、不报错，
> 但逻辑完全变了。改完必须**看渲染结果**验证，不能只看 `node --check`。

## 五、附带修复：HBase Thrift 断连

测试时发现顶栏显示 `chunk=13124`、`脂批 9,854`，与真实的 `11,780 / 8,510` 不符。

排查后端日志：

```
HBase 连接异常，重连重试 1/3: TTransportException(type=1,
  message="Could not connect to ('master', 9090)")
```

**原因**：容器重启后 HBase Thrift 服务不会自动启动。

**修法**：
```bash
docker exec -d master bash -lc "hbase thrift start > /logs/hbase-thrift.log 2>&1"
docker restart hlm-api
```

恢复后 `health` 返回 `chunk=11780, pizhu=8510, hbase=ok`。

> **注意**：HBase 断连时后端不是报错，而是返回**错误的统计数字**（13124/9854）——
> 这种"静默错误"比直接崩溃更危险。健康检查应包含 `hbase=ok` 判断。

### 7.2 现在可以说的话

**答辩/文档里可以这样表述**：

> 人物关系图采用**双层关系视图**：
> - **语义层**：来自 4 个开源红学知识图谱的 683 条三元组（丫鬟/父子/夫妻等 76 种关系类型）
> - **共现层**：来自本项目 **MapReduce cooccur 作业**产出的 588 对聚合共现
>
> 两层可独立开关，语义层给"是什么关系"，共现层给"关系有多紧密"。

这样说法**既准确又体现了 Hadoop 贡献** —— 不再是"关系图和 Hadoop 无关"。

## 九、局限

| # | 局限 | 说明 |
|:--:|:---|:---|
| 1 | 共现边无类型 | 只有"同回共现 N 次"，不知道是丫鬟还是父子 |
| 2 | 阈值是拍的 | `≥30 次` 是试出来的，不是统计推导 |
| 3 | 只覆盖 33 个节点 | 共现数据只涉及高频人物 |
| 4 | 共现 ≠ 关系 | 同回出现不代表有关系（如两个陌生人同一场宴会） |

> 第 4 条最需要注意：共现只是**相关**，不是**因果/关系**。
> 界面上应保留「共现」这个措辞，不能叫「亲密关系」。
