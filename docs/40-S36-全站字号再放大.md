# S36 · 全站字号再放大（含左侧栏，不加宽侧栏）

> 日期：2026-10-26
> 需求：「考虑再放大字号（全部放大，包括左边栏，但不增加左边栏栏宽）。这次放大时可能比较困难。」

---

## 一、为什么这次"比较困难"

前面已经放过两轮（S29-1 / S29-2），字号中位数已到 17px。
再做一次全局乘法会连锁出问题：

| 风险 | 说明 |
|:---|:---|
| ① 大标题溢出 | 24~45px 的标题再放大会撑破卡片/图表容器 |
| ② 字号层级被压平 | 乘法放大时 15.0 和 15.5 都落到 17.1，视觉层次消失 |
| ③ 左侧栏截断 | 侧栏固定 168px，文字放大会被 `ellipsis` 吃掉 |
| ④ 固定尺寸徽标爆掉 | `.hp-num` 宽 26px 高 26px，字号 20px 就装不下 |
| ⑤ 顶栏竖排 | 顶栏高 68px，字号放大后「配置」被挤成竖排 |

---

## 二、核心解法：平滑加性放大（不用乘法）

```python
nv = v + 2.3 × (12 / max(v, 12))^0.35      上限 v+2.3，超过 22px 不动
```

| 原字号 | 放大后 |
|---:|---:|
| 9.5 | 11.8 |
| 12 | 14.3 |
| 13.5 | 15.7 |
| 15 | 17.1 |
| 17 | 19.0 |
| 20 | 21.8 |
| >22 | 不变 |

**关键性质**：增量随原字号单调递减 → 保证 `v1 < v2` 时 `nv1 < nv2`，字号层级完整保留。

> 试过「分层倍率」（≤12 ×1.18 / 12~15 ×1.14 / …），结果 15.0 和 15.5 都变成 17.1，
> 层级被压平，设计看起来会"糊"。加性方案解决这个问题。

## 三、左侧栏：不加宽，靠腾空间

**问题**：侧栏固定 168px，文字从 13.5 放大到 15.5，5 个汉字要 78px。

**解法**：从别处省宽度——

| 项 | 原值 | 新值 | 省出 |
|:---|:---|:---|---:|
| 内边距（左右各） | 10px | 8px | 4px |
| 图标列宽 | 22px | 18px | 4px |
| 图标与文字间距 | 10px | 8px | 2px |
| **文字可用宽度** | **116px** | **126px** | **+10px** |

预算复核：`168-16-18-8 = 126px` 可用，5 字 @15.5px = 78px，**余量充足**。

> 侧栏字数最多的是「癸酉本探究」「AI 问答」（5 字）。

同步调整：
- `.rail-item` 13.5 → **15.5px**（+15%）
- `.rail-item .ico` 15px（保持不超列宽 18px）
- `.rail-item .badge` 9.5 → 10.5px
- `.mini-stat b` 15 → 16.5px
- `.mini-stat span` 10 → 11.5px
- 侧栏总宽 **保持 168px 不变**

## 四、连带修复的 5 处布局问题是

字号放大本身是一行正则，真正的工作量在这里：

### 4.1 顶栏竖排

「配置」按钮被挤成竖排显示。

```css
--topbar-h: 68px → 76px;                    /* 高度不够 */
.topbar-right .btn { white-space: nowrap; flex: none; }   /* 禁止换行 */
padding: 0 20px → 0 14px;                   /* 收紧内边距 */
gap: 10px → 8px;
```

### 4.2 模型名被截断

`deepseek-flash` 显示成 `deepseek`。

```css
.model-picker select { max-width: 210px → 300px; }
```

### 4.3 状态胶囊被压住

「RAG 就绪 · 11780 chunk / 11780」尾部被右侧按钮遮住。

```css
.status-pill { flex: 1 1 auto; max-width: 340px; text-overflow: ellipsis; }
```

### 4.4 方形序号徽标装不下字

`.hp-num` 宽 26px 高 26px，字号已到 20px → 必须同步放大容器。

| 选择器 | width | height |
|:---|:---|:---|
| `.hp-num` | 26 → **35px** | 26 → **31px** |
| `.gy-num` | 25 → **33px** | 25 → **29px** |
| `.pr-num` | 25 → **33px** | 25 → **29px** |
| `.pr-stage-no` | 21 → **31px** | 21 → **27px** |
| `.cite .idx` | 16 → **29px** | 16 → **26px** |

规则：`width ≥ font-size × 1.75`，`height ≥ font-size × 1.55`

### 4.5 阅读页标题被截断

`.rd-title .h` 带 `white-space: nowrap; text-overflow: ellipsis`，字号 21.9px 时
「第3回 金陵城起复贾雨村 荣国府收养林黛玉」显示成「第3回 金陵城起复…」。

```css
.rd-bar { flex-wrap: wrap; }                    /* 允许换行 */
.rd-title .h { white-space: normal; overflow: visible; }
```

### 4.6 人物关系页图例遮住画布

图例固定在左下，字号放大后行数撑高，向上长到画布中央。

```css
.gr-legend { max-height: 42%; overflow-y: auto; font-size: 14.5px; }
```

## 八、教训

**字号放大从来不是"改数字"，是"改数字 + 修布局"。**

这次 327 处字号改动本身是脚本一行正则，但真正花时间的是 6 处连带问题：
顶栏竖排、下拉截断、状态胶囊被压、徽标装不下、标题 ellipsis、图例遮画布。
**每一处都只能靠实际打开页面看才能发现**——静态检查（语法、CSS 合法性）全部通过，
但页面就是不对。

另一条：**乘法放大压平层级**。
如果你发现放大后"字都差不多了"，说明用了统一倍率。改成加性、
且增量随原值递减，就能保住设计层次。
