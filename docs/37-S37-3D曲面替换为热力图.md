# S37 · 人物出场曲面（3D）→ 热力图

> 日期：2026-10-27
> 用户需求：「人物出场曲面（3D）也不太直观，或者说有点丑，你看一下有没有改进或替换方法？」

---

## 一、问题的本质

### 1.1 数据形状与图表形式不匹配

数据是 `person_hui_matrix.json`：

| 维度 | 内容 | 规模 |
|:---|:---|:---|
| 行 | 人物（Top-30，按全书提及量） | 30 |
| 列 | 回次（1–80） | 80 |
| 值 | 该回提及次数 | 0–117 |

**本质是一个 30×80 的矩阵。**

而原来的 3D 曲面把它画成 **2,400 根立体柱子** —— 这是「矩阵数据用 3D 柱状图表达」的典型错误。

### 1.2 具体问题

| # | 问题 | 说明 |
|:--:|:---|:---|
| 1 | **遮挡** | 2,400 根柱子前后重叠，前排挡住后排 |
| 2 | **透视失效** | 远处柱子在投影下被压扁，数值无法读取 |
| 3 | **交互成本** | 需拖拽旋转才能看清局部，且旋转后另一边又被挡 |
| 4 | **视觉噪音** | 柱子本身占据大量像素，颜色反而看不清 |

截图对比（改前）：柱林密布，只有宝玉/贾母等少数高峰能辨认，其余"糊成一片"。

## 二、替换方案：热力图

### 2.1 为什么热力图合适

| 优势 | 说明 |
|:---|:---|
| **无遮挡** | 一格一值，2,400 个格子全部可见 |
| **一屏看完** | 80 回 × 30 人物的整体分布规律一眼可见 |
| **颜色即数值** | 色深=提及次数，热点自然浮现 |
| **可精确定位** | 悬停即显示「人物·回次·次数」 |
| **可高亮对比** | 点击行 → 该人物独特的时间分布形态与其他形成对比 |

### 2.2 视觉设计

```
       1    5    9   13   17   21   25   29   33   37   41   45   49   53   57   61   65   69   73   77   80
贾宝玉 ▓▓▓▓▓▓▓▒▒▓█▓▒▓▓▓▓▒▒▓▓▓▒▓▓▓▓▓▓▒▓▓▓▓▓▓▒▓▓▓▓ 第19回·117
贾母   ▓▒▒▓▒▒▒▓▓▒▒▒▒▓▒▒▒▒▒▒▓▓▓▒▒▒▒▓▓▓▓▒▒▓▓▓▓▓▓▓ 第40回·86
王熙凤 ▒▒▒▓▓▒▒▒▒▓▓▒▒▒▓▒▒▒▒▒▒▒▓▒▓▓▓▒▒▒▒▒▒▓▓▓▓▓ 第74回·66
...
```

**配色**：红系渐变（与项目主色 `#b03a2e` 一致）

```javascript
// 浅粉 → 深朱
const r0 = 250, g0 = 240, b0 = 228;   // 0 值附近
const r1 = 155, g1 = 40,  b1 = 28;    // 峰值

// 幂次 0.55 让低值也可辨（线性会把低值压成一片白）
const a = Math.pow(v / maxV, 0.55);
```

**为什么用幂次而非线性**：
数据分布极不均（宝玉峰值 117，多数人物多数回是 0–5），
线性的 5/117 = 4% 几乎看不出来，`5/117` 经 `^0.55` 后变成约 21%，能看见了。

### 2.3 布局

```javascript
const pad = { t: 22, r: 78, b: 34, l: 82 };
//           ↑顶部留列标签  ↑右侧留峰值标注  ↑底部留"回次"  ↑左侧留人物名
```

- **行序**：按 `total`（全书提及量）降序 —— 重要人物在上，符合阅读习惯
- **右侧标注**：每个人物的峰值回次与数值（`第19回·117`），便于快速定位
- **列标签**：每隔 `ceil(80/20)=4` 回标一个，避免拥挤

## 三、交互

### 3.1 悬停

```
┌─────────────────────┐
│ 贾探春 · 第40回 · 9 次 │
└─────────────────────┘
         ↓
        [▓]  ← 朱红描边高亮当前格
```

- 跟随鼠标位置，边界自动翻转（不会超出画布）
- 当前格加朱红描边

### 3.2 点击高亮

点击任意格 → 该**行**高亮：
- 行标签变朱红加粗
- 该行格子保持原色
- 其他行 `globalAlpha = 0.45` 淡化

再次点击取消。

**为什么高亮整行而不是单格**：
用户看这张图通常是想问「某个人物的出场节奏是怎样的」，
所以高亮整行、对比其他人，比单格更有意义。

### 3.3 底部提示文字联动

```javascript
onSelect: (name) => {
  sn.textContent = name
    ? `已高亮「${name}」· 再次点击取消`
    : '行=人物（按全书提及量降序）· 列=回次（1–80）· 右侧标注峰值回次';
}
```

## 四、踩的坑：淡化过度

### 4.1 现象

第一版点击高亮时，其他行 `globalAlpha = 0.22`，结果**整张图几乎看不见了**：

```
点击前：清晰的热力矩阵
点击后：一行亮 + 一片雾白，反而是"更差了"
```

### 4.2 原因

热力图的**信息密度靠颜色承载**，淡化 78% 后低值格（本来就是浅色）
变成接近白色，整张图的分布形态消失了。

这和力导向图不同 —— 节点图淡化边是"减少干扰"，热力图淡化是"删除信息"。

### 4.3 修法

```javascript
// 改前
ctx.globalAlpha = dim ? 0.22 : 1;
// 改后
ctx.globalAlpha = dim ? 0.45 : 1;   // 淡化但仍可读
```

同时行标签淡化色从 `paper3`（几乎白）改为 `ink3`（灰蓝），保持可读。

## 五、渲染性能

用的是 **Canvas 2D 一次性绘制**，不是 WebGL：

- 2,400 个 `fillRect` + 30 个文字标签
- 首帧约 20–30 ms
- 交互时用 `requestAnimationFrame` 合并重绘（避免 mousemove 高频触发）

**不需要 WebGL** —— 热力图的复杂度远低于原来的 3D 曲面。
