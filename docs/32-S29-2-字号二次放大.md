## 二、二次放大后又撞到的 2 处布局问题

### 2.1 顶栏模型名被截断

**现象**：显示成 `DeepSeek · deepseek-fla`，最后几个字母消失。

**原因**：`.model-picker select` 的 `max-width: 220px` 是按 12.5px 设计的，
字号涨到 17.5px 后，"DeepSeek · deepseek-flash" 需要约 280px。

**修法**：
```css
.model-picker select { max-width: 220px → 300px; }
```

### 2.2 侧栏底部统计被切掉

**现象**：`81 / 8,510 / 120` 三个数字贴着屏幕最底边，下面的「回 / 批语 / 人物」标签看不见。

**根因**：左侧栏虽然在字号上还原了，但**导航项的行盒被 emoji 撑高** ——
每个错略项实际占约 70px（而非预期的 38px），9 项共 630px，超出可视高度 685px。

**修法**：
```css
.rail-item { padding: 9px → 6px; line-height: 1.25; }  /* 收紧 */
.rail-item .ico { line-height: 1.1; }
.rail { padding-bottom: 18px; }                          /* 底部留白 */
```

改完 9 项共约 290px，底部统计完整可见。

## 六、教训

| # | 教训 |
|:---|:---|
| 1 | **「整栏不放大」要连容器尺寸一起回退**。只还原字号不回退 `--rail-w`，会留下 47px 空白。 |
| 2 | **emoji 会撑高行盒**。`.rail-item` 字号回到 13.5px 后，间距仍按 70px 算 —— 必须显式设 `line-height` 并收紧 `padding`。 |
| 3 | **放大后要重查固定宽度**。`max-width: 220px` 这种按旧字号算的值，放大后必然截断文字。 |
| 4 | **两遍放大的边界要按当前值算，不是原始值**。第二遍曲线基于「一遍后」的字号，所以系数比第一遍小。 |
| 5 | **验证脚本本身也会写错**。这次正则多匹配了一个 `{`，导致「正文 16.5px」被误报成「继承」，差点误判。 |
