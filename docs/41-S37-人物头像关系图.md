## 二、数据：为什么必须先做去重

### 2.1 原始图谱的问题

全量图谱是四个开源来源合并的，同一对关系被重复记录。以林黛玉与薛宝钗为例：

```
黛玉 --[友]-->    宝钗
黛玉 --[朋友]-->  宝钗
宝钗 --[朋友]-->  黛玉     ← 反向重复
```

林黛玉在原图里「度=29」，但**实际只有 8 个不同关系对象**。
如果不处理，15 个节点之间会画出几倍粗的重叠线，完全看不清。

### 2.2 处理规则

| 步骤 | 做法 |
|:---|:---|
| ① 无序对去重 | `frozenset((a,b)) + 归一化关系名` 作为唯一键 |
| ② 关系词归一 | 友/好友/朋友 → **朋友**；丈夫/妻/妻子 → **夫妻**；丫鬟/奴仆/侍女 → **主仆**；表兄妹/姑表 → **表亲** |
| ③ 一对多关系合并 | 同一对人物有多种关系时，按权重取前 2 个，用 ` / ` 连接 |
| ④ 剔除孤立点 | 无任何内部边的人物（说明其关系对象不在本图内） |

**效果**：主要人物间原始 54 条边 → 去重 26 → 合并 23 条。

### 2.3 人物选取：为什么是这 16 个

最初选了「度数最高的 14 个有画像人物」，结果**王熙凤、秦可卿变成孤岛**——
她们的关系全指向贾琏、王夫人、秦业、丫鬟等「非主角」：

```
王熙凤: 16 条边，全部指向 贾琏/王夫人/巧姐/邢夫人/丫鬟…
秦可卿:  8 条边，全部指向 贾蓉/秦业/瑞珠/宝珠…
```

**修法**：补入桥梁人物（贾琏、王夫人），让王熙凤通过「夫妻 / 姑侄」连进主网。
最终 15 个有效节点（秦可卿仍孤立，已剔除）。

## 三、实现

### 3.1 新增文件

| 文件 | 说明 |
|:---|:---|
| `web/public/js/chart_avatar.js` | 头像关系图渲染器（~400 行） |
| `scripts/s37_1_build_main_relations.py` | 生成精简关系数据（含去重与归一化） |
| `web/data/main_relations.json` | 输出数据（15 节点 / 23 边） |
| `web/public/img/avatars87/*.png` | **87 版圆形头像（15 张，220×220）** |
| `web/public/img/avatars/*.png` | 改琦版圆形头像（29 张，备选，公有领域） |

### 3.2 头像处理

```python
# 正方形裁剪 → 圆形遮罩 → 200×200 PNG
side = min(W, int(H * 0.55))
left = (W - side) // 2
top  = int(H * 0.20)          # 从 20% 处开始，覆盖头肩
sq = im.crop((left, top, left+side, top+side)).resize((200, 200))
mask = 圆形 ellipse
```

**关于精度的如实说明**：改琦画是「人物 + 树石背景 + 题跋」的竖幅，
最初尝试多种自动定位面部的方法都失败了：

| 尝试 | 结果 |
|:---|:---|
| OpenCV Haar 人脸检测 | 木刻线描检出率低，且误检树石 |
| 墨迹密度大窗搜索 | 命中树石（满布纹理） |
| 连通域 + 圆度筛选 | 阈值过严，0 候选 |
| 「上发-中脸-下衣」三段特征 | 已知正确样本上仍有 ±0.10 偏差 |
| 中心留白搜索（向量化） | 17/27 有解，但 score 多为负 |

**最终采用「整幅中段圆形裁剪」**：虽然脸部较小，但 27 张**全部保证是人物**，
不会出现「圆里是一棵树」。这个取舍是有意的——**宁可小，不可错**。

### 3.3 渲染要点

| 特性 | 实现 |
|:---|:---|
| 头像圆形 | `ctx.clip()` 圆形 + `drawImage` 铺满 |
| 缺图兜底 | 家族色圆形 + 姓氏首字 |
| 关系文字 | 画在连线中点，带白底胶囊避免压线 |
| 线不压头像 | 按单位向量裁剪到圆周外 2px |
| 力导向 | 斥力 + 弹簧（关系越强弹簧越短）+ 向心，15 节点收敛快 |
| 交互 | 拖节点 / 滚轮缩放 / 拖空白平移 / 点击选中（非邻居淡化） |
| 顶部避让 | `padTop = r + 52`，让开「2D/3D/和弦图/人物头像图」按钮栏 |

### 3.4 接入

人物关系页视图切换从 3 个变 4 个：

```
[ 2D 平面 ]  [ 3D 立体 ]  [ 和弦图 ]  [ 人物头像图 ]
```

头像模式下**自动隐藏底部图例**（节点自带头像和姓名，图例会遮挡画布）。

## 六、已知不足（如实说明）

1. **剧照版权**：仅限课堂教学使用；公开前必须替换为公有领域素材（改琦版本已保留在
   `img/avatars/`，改一行路径即可切回）。
2. **古装剧照与原著描写有出入**：87 版是二次创作，人物服饰形象属于剧组设计，
   不能当作原文考据依据——关系图里它只承担「标识人物」的功能。
3. **关系名有合并**：一对人物有多种关系时只显示前 2 个，完整列表在
   `main_relations.json` 的 `all_relations` 字段里。
4. **3D 视图的伏笔**：`all_relations` 已在数据里，若后续要做「按关系类型筛选」可直接用。
