## 二、数据：为什么必须先做去重

### 2.1 原始图谱的问题

全量图谱是四个开源来源合并的，同一对关系被重复记录。以林黛玉与薛宝钗为例：

```
黛玉 --[友]-->    宝钗
黛玉 --[朋友]-->  宝钗
宝钗 --[朋友]-->  黛玉     ← 反向重复
```

林黛玉在原图里「度=29」，但**实际只有 8 个不同关系对象**。
如果不处理，15 个节点之间会画出几倍粗的重叠线，完全看不清。

### 2.2 处理规则

| 步骤 | 做法 |
|:---|:---|
| ① 无序对去重 | `frozenset((a,b)) + 归一化关系名` 作为唯一键 |
| ② 关系词归一 | 友/好友/朋友 → **朋友**；丈夫/妻/妻子 → **夫妻**；丫鬟/奴仆/侍女 → **主仆**；表兄妹/姑表 → **表亲** |
| ③ 一对多关系合并 | 同一对人物有多种关系时，按权重取前 2 个，用 ` / ` 连接 |
| ④ 剔除孤立点 | 无任何内部边的人物（说明其关系对象不在本图内） |

**效果**：主要人物间原始 54 条边 → 去重 26 → 合并 23 条。

### 2.3 人物选取：为什么是这 16 个

最初选了「度数最高的 14 个有画像人物」，结果**王熙凤、秦可卿变成孤岛**——
她们的关系全指向贾琏、王夫人、秦业、丫鬟等「非主角」：

```
王熙凤: 16 条边，全部指向 贾琏/王夫人/巧姐/邢夫人/丫鬟…
秦可卿:  8 条边，全部指向 贾蓉/秦业/瑞珠/宝珠…
```

**修法**：补入桥梁人物（贾琏、王夫人），让王熙凤通过「夫妻 / 姑侄」连进主网。
最终 15 个有效节点（秦可卿仍孤立，已剔除）。

### 3.2 头像处理

```python
# 正方形裁剪 → 圆形遮罩 → 200×200 PNG
side = min(W, int(H * 0.55))
left = (W - side) // 2
top  = int(H * 0.20)          # 从 20% 处开始，覆盖头肩
sq = im.crop((left, top, left+side, top+side)).resize((200, 200))
mask = 圆形 ellipse
```

**关于精度的如实说明**：改琦画是「人物 + 树石背景 + 题跋」的竖幅，
最初尝试多种自动定位面部的方法都失败了：

| 尝试 | 结果 |
|:---|:---|
| OpenCV Haar 人脸检测 | 木刻线描检出率低，且误检树石 |
| 墨迹密度大窗搜索 | 命中树石（满布纹理） |
| 连通域 + 圆度筛选 | 阈值过严，0 候选 |
| 「上发-中脸-下衣」三段特征 | 已知正确样本上仍有 ±0.10 偏差 |
| 中心留白搜索（向量化） | 17/27 有解，但 score 多为负 |

**最终采用「整幅中段圆形裁剪」**：虽然脸部较小，但 27 张**全部保证是人物**，
不会出现「圆里是一棵树」。这个取舍是有意的——**宁可小，不可错**。

### 3.3 渲染要点

| 特性 | 实现 |
|:---|:---|
| 头像圆形 | `ctx.clip()` 圆形 + `drawImage` 铺满 |
| 缺图兜底 | 家族色圆形 + 姓氏首字 |
| 关系文字 | 画在连线中点，带白底胶囊避免压线 |
| 线不压头像 | 按单位向量裁剪到圆周外 2px |
| 力导向 | 斥力 + 弹簧（关系越强弹簧越短）+ 向心，15 节点收敛快 |
| 交互 | 拖节点 / 滚轮缩放 / 拖空白平移 / 点击选中（非邻居淡化） |
| 顶部避让 | `padTop = r + 52`，让开「2D/3D/和弦图/人物头像图」按钮栏 |

### 3.4 接入

人物关系页视图切换从 3 个变 4 个：


# S37-2 · 补充贾政/贾母/贾元春 + 修复亲属方向

> 反馈：「贾宝玉和王夫人的关系应为母子而非父子，此外考虑添加贾元春、贾政和贾母等节点」

## 一、Bug：为什么显示成「父子」

原始图谱里同一对亲属关系存了**正反两条**：

```
贾宝玉 --[儿子]--> 王夫人     语义：宝玉是儿子    → 母子
王夫人 --[母亲]--> 贾宝玉     语义：王夫人是母亲  → 母子
```

我最初的归一化表把「儿子」映射成 `父子`、「母亲」映射成 `母子`，
然后按出现次数取前两个 → 拼出 `父子 / 母子`，
又打了个「子女类只留一条」的补丁，结果**错误地留下了 `父子`**。

**根因**：归一化只看了词面，没看「谁是谁的谁」。

## 二、修法：按对方节点的实际性别判定

```python
KIN = {"父亲":"父","母亲":"母","儿子":"子","女儿":"女", ...}

FEMALE = {"贾母","王夫人","林黛玉","薛宝钗", ...}   # 女性人物表

def kin_label(role, other_name):
    """role=前者的角色；other_name=后者姓名 → 按后者性别选字"""
    female = other_name in FEMALE
    if role == "子" and not female: return "父子"
    if role == "子" and female:     return "母子"   # ← 王夫人是女的 → 母子
    ...
```

这样：
- `贾宝玉 --[儿子]--> 王夫人` → role=子，对方女性 → **母子** ✅
- `王夫人 --[母亲]--> 贾宝玉` → role=母，对方男性 → **母子** ✅
- 两条归一化后 key 相同 → 自然去重

## 三、方向统一

组合词「母子/父子/母女/父女」本身隐含「长辈在前」，
所以再用**逐对辈分表**保证长辈出现在 source 位置：

```python
elder_pairs = {("贾母","贾政"),("贾母","贾宝玉"),("贾政","贾宝玉"),...}
if (dst, src) in elder_pairs: src, dst = dst, src
```

结果：`贾母 —母子— 贾政`（而不是反过来的 `贾政 —母子— 贾母`）。

## 五、布局重做：两圈 + 标签避让
