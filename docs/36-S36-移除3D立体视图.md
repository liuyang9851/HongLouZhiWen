# S36 · 移除人物关系页的 3D 立体视图

> 日期：2026-10-27
> 用户需求：「人物关系里的 3d 立体图不太直观，去掉吧。」

---

## 一、改动前的问题

人物关系页原有 **4 个视图切换**：

```
[2D 平面] [3D 立体] [和弦图] [人物头像图]
```

3D 立体视图的问题：
- WebGL 透视投影下，**远处节点被近处遮挡**，人物密集区看不清谁是谁
- 鼠标拖拽旋转需要学习成本，不像 2D 拖拽那样直觉
- 深度信息对"看关系"帮助不大 —— 关系是二维的（谁连谁），不是三维的

## 三、顺带修的一个布局问题

### 3.1 现象

截图发现顶部提示文字框**遮挡了视图切换按钮**：

```
[拖拽空白处平移·拖拽节点移动·滚轮]  ← 提示框
              [2D 平面][和弦图][人物头像图]  ← 被压住
```

### 3.2 原因

```css
.gr-tip {
  position: absolute; left: 16px; top: 16px;
  max-width: calc(100% - 260px);   /* 只给右上角「重置」按钮留了位置 */
  font-size: 18.6px;               /* 字号过大，占宽太多 */
}
```

- `max-width` 只考虑了「重置」按钮（约 80px），没考虑切换按钮组（3 项约 300px）
- `font-size: 18.6px` 过大（正常 UI 提示是 12~14px）

### 3.3 修法

```css
.gr-tip {
  position: absolute; left: 16px; top: 16px;
  max-width: calc(100% - 430px);   /* S36：给右上角按钮组 + 「重置」留位置 */
  font-size: 14px;                 /* 从 18.6px 降到 14px */
}
```

## 五、排查过程中的一个假警报

测试「人物头像图」时发现**画布空白**，一度以为是代码 bug。

排查发现：**我访问的端口不对**。

```
服务实际运行在 5173（因为重启时没传 HLM_WEB_PORT，走了 server.js 的默认值）
但我访问的是 3380（之前的端口）
→ 静态资源能加载（可能命中缓存），/data/*.json 全部连接被拒
→ 头像图依赖 /data/main_relations.json → 空白
```

改到 5173 后，头像图完全正常（15 个头像 + 连线）。

**教训**：`/data/*.json` 这类异步数据请求失败时，
`fetch().catch()` 只会在控制台打一条 warn，界面上表现为**静默空白**。
应在失败时给用户可见提示（当前代码有这个逻辑，但走的是「数据未生成」的提示，
实际原因是「连接失败」，提示文案会误导）。

**改进方向**（未实施）：区分「数据文件不存在」和「请求失败」两种情况，给不同提示。

## 七、保留的 3D 功能

**统计信息页的「人物出场曲面（3D）」保留**（那是另一个界面）：

- 位置：`#/stats` 页
- 用途：横轴回次 × 纵轴人物 × 高度=出场次数，形成三维曲面
- 这个 3D **有明确的空间语义**（三个维度都有意义），与关系图的情况不同

如果用户也觉得那个不直观，可以再要求移除。
