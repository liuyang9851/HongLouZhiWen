# S24 · 欢迎页架构图（重点展示 Hadoop 生态）

> 日期：2026-10-24
> 需求：「欢迎页中绘制一个简单的架构图来展示程序架构，重点展示 hadoop 生态部分」

---

## 一、设计思路

### 1.1 为什么这样分层

架构图按「**数据自下而上流动**」组织，因为数据流是这个项目最本质的逻辑：

```
原始语料 → HDFS 存储 → MapReduce 批统计 → HBase 索引 → 三路检索 → LLM 生成
```

5 层从上到下排布（视觉上自上而下，但箭头表示数据向上流），
**Hadoop 生态占 3 层（HDFS / HBase / 计算分析），图面占比约 55%**。

### 1.2 为什么用 SVG 而不是图片

| 方案 | 优点 | 缺点 |
|:---|:---|:---|
| **SVG（采用）** | 可缩放、可打印、文字可搜索、零依赖、随数据更新 | 需手写 |
| PNG 图片 | 简单 | 模糊、不可检索、改一次重画一次 |
| Mermaid/Graphviz | 自动化 | 样式受限于工具，无法精细控制 |

**手写 SVG**：约 340 行，完全可控。

### 2.3 Hadoop 生态部分的特别强调

用了三层来承载，且每层都给了**具体实物**（不是抽象概念）：

**① HDFS 层**
- 三个具体目录：`/hlm/`（原始）、`/hlm/mrin→/hlm/mrout`（批统计）、`/hlm/derived`+`/hlm/warehouse`（派生）
- 每层都标注了体积和行数

**② HBase 层**
- **5 张表全部展开**，每张表给出行数 + 列族结构 + 用途
- 列族格式如 `d:text` `m:hui/version`（与真实 schema 一致）
- 标注 Thrift:9090 端口

**③ 计算层**
- 6 个组件并列：MapReduce / Spark / Hive / ZooKeeper / Flink / Storm
- 全部带版本号

## 三、视觉设计

### 3.1 配色

| 层 | 主色 | 含义 |
|:---|:---|:---|
| HDFS | `#2f6f4e` 绿 | 存储（稳重） |
| HBase | `#b03a2e` 红 | 在线服务（醒目，呼应品牌色）|
| 计算分析 | `#7a6a52` 褐 | 批处理（低调）|
| RAG 应用 | `#2f4858` 深蓝 | 应用层 |
| 生成展示 | `#5b6b7a` 灰蓝 | 外围 |

配色遵循：**存储层用绿色（生命/持久），服务层用红色（热度/在线）**，
与应用层形成对比，让 Hadoop 部分在视觉上"沉"在下半部分。

### 3.2 数据流箭头

左侧有一条**竖向虚线箭头**，标注「数据流：存储 → 索引 → 检索 → 生成」，
贯穿五层，直观表达"数据从下往上流"。

层内也有横向箭头（HDFS 层内：原始 → MR → 派生）。

### 3.3 字号层次

| 元素 | 字号 | 字重 |
|:---|:---|:---|
| 层标题 | 12.5 | 700 |
| 节点名 | 11 | 700 |
| 说明文字 | 9.5 | 400 |
| 技术细节（mono） | 8.5~9.5 | 400 |

用 `monospace` 字体显示路径、行数、列族 —— 与正文区分，体现"技术参数"。

## 四、实现

### 4.1 新增文件

| 文件 | 行数 | 职责 |
|:---|---:|:---|
| `web/public/js/arch_diagram.js` | ~340 | SVG 生成函数 |

### 4.2 核心代码结构

```javascript
export function renderArchDiagram() {
  const C = { hadoop:'#2f6f4e', hbase:'#b03a2e', ... };

  // 小工具
  const box  = (x,y,w,h,fill,stroke,rx) => `<rect .../>`;
  const txt  = (x,y,s,size,fill,weight,anchor) => `<text .../>`;
  const mono = (x,y,s,size,fill,anchor) => `<text font-family="Consolas".../>`;
  const arrow = (x1,y1,x2,y2,color,dashed) => `<line marker-end="url(#arr)" .../>`;

  return `<svg viewBox="0 0 900 720">...`;
}
```

**为什么直接返回字符串而不是操作 DOM**：可以嵌进模板字符串，且方便复用（如导出独立预览页）。

### 4.3 响应式

```css
.hp-arch-wrap { overflow-x: auto; }
.hp-arch-wrap svg { min-width: 660px; }
```

- 大屏：`width:100%` 自适应缩放
- 小屏：`min-width:660px` + 横向滚动（不压缩变形）

## 五、踩的 2 个坑

### 坑1：`master` 节点描述文字溢出边框

第一版写的是：
```
NameNode · ResourceManager · HMaster · ZooKeeper
```
24 个字符 + 分隔符，在 240px 宽的框里溢出。

**修法**：缩写 + 缩小字号
```
NameNode·ResourceMgr·HMaster·ZK     (font-size: 8)
```

### 坑2：中文数字「贰」被渲染成生僻字「贑」

截图发现章节编号「贰」显示成「贑」。

**原因**：`font-feature-settings` 的中文 ligature 替换 + 字体回退问题。
某些字体把「贰」的字形映射到了罕用变体。

**修法**：改用阿拉伯数字 `1 2 3 4 5`

```javascript
const mapping = { 壹:'1', 贰:'2', 叁:'3', 肆:'4', 伍:'5', 陆:'6' };
```

> 这是个"看起来是小问题但很显眼"的 bug —— 中文排版在 Web 上比想象中脆弱。
