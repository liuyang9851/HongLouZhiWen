## 一、脂批大全乱码：73 条 → 0 条

### 1.2 两类乱码

**A. 「一?一」模式（48 条）—— 着重号丢失**

原书用**着重号**标强调字。转成 Markdown 时：
- 被强调的字 → `U+FFFD`
- 着重号本体 → `一`

```
gitbook 源：浪子一�一女
PDF 原文：  浪子淫女          ← 「淫」被加着重号
```

**B. 生僻字（25 条）**

```
《离一�一》      → 《离骚》
《��词》         → 《姽婳词》
�，音垒。周器也   → 罍，音垒。周器也
```

### 1.3 修复方法（4 级降级）

| 级别 | 方法 | 修复数 |
|:---|:---|---:|
| ① | **PDF 上下文回填**：用乱码前后 15 字在 PDF 里定位，取回真实字形 | 29 |
| ② | **跨源回填**：在抚琴居校本/癸酉本脂批里找同一条 | 6 |
| ③ | **人工对照表**：逐条确认（依据写在代码注释里） | 17 |
| ④ | **着重号清理**：`一?一` 整体删除（着重号本体不该留在正文） | 26 |

**最终结果：73 → 0 条，零 U+FFFD。**

### 1.4 踩过的 4 个坑

| # | 坑 | 修法 |
|:---|:---|:---|
| 1 | 用「一」和「女」做上下文去 PDF 找，找不到 —— 因为 PDF 里没有那两个「一」 | 匹配前先 `strip_emphasis()` 剥离着重号残留 |
| 2 | 一条批语有**多处**乱码，第一处修好后第二处失败就 `break`，整条没有写回 | 单处失败改为「跳过继续」，累加计数后只要修过就写回 |
| 3 | 标点差异导致定位失败（`艳极，淫极！` vs PDF `艳极，淫极。`） | 建 PDF 的第二套「标点归一化」索引 |
| 4 | 对照表写 `《离?》`，实际文本是 `《离一?一》`，匹配不上；先 strip 后对照表又漏了 | 先跑对照表（乱码还在时），再规范化着重号形式跑一遍，最后才 strip |

## 二、抚琴居校本残余截断：50 条 → 39 条

### 2.1 S12 之后的状态

S12 修复了 4 种截断模式（补字/跨页/双行夹批/行内标记），1,315 条得到修复。
但仍有 **50 条**以逗号/助词结尾，疑似截断。

### 2.2 新增的第 5 种修复策略：末尾续接

旧方法用 `extract_from_page(want_start=...)` 从**批语开头**重新提取，
但起点定位在部分版面失败（批语被 EUDC 打断、或跨了 3 页以上）。

**新策略**：用该条**最后 8 个字**在 PDF 里定位，从那里往后继续收集楷体，
直到遇到真正的正文。

```python
def continue_after(tail_text, page):
    last8 = norm(tail_text)[-8:]        # 用末尾定位，不用开头
    # 找到位置后，继续收集后面的楷体行
    # 遇到「同行且靠右的宋体」→ 双行夹批正文，跳过
    # 遇到「不同行的宋体」→ 批语结束
```

## 六、教训

| # | 教训 |
|:---|:---|
| 1 | **乱码要先判断「源坏了」还是「提取坏了」**。本轮 73 条乱码，源文件里就有 U+FFFD —— 这种情况只能靠**另一个来源**或**人工判断**，不能指望改提取逻辑解决。 |
| 2 | **同一个「字」在不同源里可能用不同字形**。第17回我猜「玉珕」，PDF 是「玉蕗」。**必须回原文验证，不能凭语感猜。** |
| 3 | **`break` 会吞掉已完成的成果**。多处乱码时第一处成功、第二处失败就 `break`，导致整条丢弃 —— 要改成「跳过继续」。 |
| 4 | **短批语不要当截断**。「谚云：」这种 3 字批语原书就是那么短，用「结尾是逗号」做检测会产生大量假阳性。 |
| 5 | **同步链路的每一环都要验证**。改了 `pizhu.jsonl` 不代表前端会变，中间还有 3 个文件要重新生成。 |
