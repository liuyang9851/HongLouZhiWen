# S17 · 可行性评估：在正文中指出批注位置

> 日期：2026-10-24
> 用户需求：「能在正文中指出批注的位置吗？这个可能有点难做，你先评估一下，难的话可以不做。」

---

## 结论（先说结果）

| 方案 | 可行率 | 难度 | 建议 |
|:---|:---:|:---:|:---|
| **A. 段落级锚定**（批语 → 正文某段） | **~68%** | 中 | ✅ **建议做** |
| B. 字符级锚定（批语 → 段内某字） | ~50% | 高 | ❌ 不建议 |
| C. 行级锚定（批语 → 正文某行） | ~68% | 中 | 与 A 相当，但前端无「行」概念 |

**建议做 A**，并且**明确标注哪些批语无法定位**，而不是硬猜。

---

## 一、为什么可行（版式分析）

### 1.1 双行夹批：批语与正文 y 坐标精确对齐

实测 p.2090：

```
y=283.5 x=54.2   SUN  '凤姐儿道："还不曾呢，如今还是吃汤药。太太'
y=243.4 x=373.8  KAI  '总是勉强。'                    ← 批语
y=243.4 x=471.6  SUN  '王夫人'                        ← 同行正文（右）
y=243.4 x=54.2   SUN  '只管放心，我已大好了。"'          ← 同行正文（左）
y=243.4 x=54.2   EUDC '\ue052\ue053'                  ← 批语代号
y=203.4 x=54.2   SUN  '见他精神复初，也就信了。'
y=203.4 x=330.1  EUDC '\ue052\ue053'
y=203.4 x=368.6  KAI  '只用此一句，便入后'             ← 批语
y=163.3 x=54.2   KAI  '文。'                          ← 批语续行
y=163.3 x=90.6   SUN  '因告诉撵逐晴雯等事，又说："怎么宝丫头私'
```

**批语与它批注的正文行共用同一个 y 坐标**（同一基线）——这是排印规则决定的，非常可靠。

### 1.2 独立块批语：无法用 y 对齐

实测 p.2122：

```
y=724.1  EUDC '\ue053'
y=724.1  KAI  '窀音肫。《左传》："窀穸之事"，墓穴幽堂也。'   ┐
y=684.6  KAI  '左贵嫔《杨后诔》："早即窀穸。"…'              │
y=645.1  KAI  '"而已反其真。"注：以死为真。'                 │ 批语
y=606.0  SUN  '余犹桎梏而悬附兮，灵格余以嗟来耶？'            │ 独立
y=606.0  EUDC '\ue052'                                      │ 成块
y=564.7  EUDC '\ue053'                                      │
y=564.7  KAI  '《庄子·大宗师》：桎梏之名。◇…'                │
…（一直到 y=364）…                                          ┘
y=325.3  SUN  '来兮止兮，君其来耶！'                          ← 正文在这里
```

批语整块占据页面中部，**没有对应的正文行 y**——这类是「回前批 / 眉批 / 长评」，锚定不了。

## 二、实测数据（抽样 300 条）

| 版式类型 | 条数 | 占比 | 能否锚定 |
|:---|---:|---:|:---:|
| **同行夹批** | 206 | **68.7%** | ✅ 可以 |
| 独立块批语 | 49 | 16.3% | ❌ 不行 |
| 定位失败（文本匹配不上） | 44 | 14.7% | ❌ 不行 |
| 纯批语页 | 1 | 0.3% | ❌ 不行 |

### 第78回完整验证结果

| 项 | 值 |
|:---|---:|
| 批语总数 | 32 条 |
| **成功锚定到段落** | **13 条（40.6%）** |
| 失败 | 19 条 |

> 第78回成功率偏低（40.6% vs 抽样 68.7%），因为这一回**
> 长评多**（《芙蓉诔》部分全是典故注释，属独立块批语）。
> 全书平均应该接近 68%。

### 锚定的准确性问题

成功案例里有一个明显缺陷：**同行正文常常只有一个字**

```
第50段  批语「世不浊，因物所混而浊也，前后便有照应。」
        同行正文「窃思女儿自临浊世，」        ← 正常
第50段  批语「方十六岁而夭，亦伤矣。」
        同行正文「其」                        ← 只有一个字！
第50段  批语「鲧刚直自命，舜殛于羽山。」
        同行正文「婞」                        ← 只有一个字
```

原因：双行夹批把正文切成碎行，PDF 提取时每个碎片是独立原语。
**锚到「段」没问题，但要给出「段内位置」就不可靠了。**

## 三、三种精度方案对比

### 方案 A：段落级（推荐）

```
批语「总是勉强。」→ 锚定到第 27 段
前端在该段右上角显示一个批语标记 ●1
点击展开该批语
```

- **可行率**：~68% 全书平均（第78回 40.6%）
- **准确率**：高（段级不会错太多）
- **工作量**：
  1. 重新提取批语，补 `page_y` 字段（1 小时）
  2. 重建 PDF 正文行坐标表（1 小时）
  3. 匹配脚本（1 小时）
  4. 前端：段落角标 + 点击展开（2 小时）
- **总计**：约 5 小时

### 方案 B：字符级（不推荐）

```
批语「总是勉强。」→ 第 27 段第 42 字（「太太」之后）
```

- **可行性**：需要把 x 坐标映射到字符序号，但双行夹批打乱了正文顺序，
  x→字符 的映射在碎行情况下误差极大
- **准确率**：估测 ~50%，会产生**错误的精确定位**（比不给更糟）
- **工作量**：8+ 小时
- **结论**：❌ 不做

### 方案 C：行级

- 与 A 等价（前端段落是自然段，不是排印行）
- 需要额外把 PDF 行合并成自然段，与 A 的工作量重复

---

## 四、我的建议

### 做方案 A，但要做三件事

**1. 补 `page_y` 数据（必须）**

当前批语只有 `page`，必须重新提取补 `y` 坐标：

```json
{
  "hui": 78,
  "text": "总是勉强。",
  "page": 2090,
  "page_y": 243.4,       ← 新增
  "page_x": 373.8,       ← 新增
  "anchor_para": 27,     ← 计算得出
  "anchor_line": "凤姐儿道：“还不曾呢..."  ← 供人工核对
}
```

**2. 明确区分「已定位」与「未定位」**

前端两类批语分开显示：

| 类型 | 展示方式 |
|:---|:---|
| 已定位（68%） | 段落右上角标 ●N，点击展开 |
| 未定位（32%） | 仍在侧栏列表，标注「位置未定」 |

**不要硬猜**——错误的锚定比没有锚定更糟，用户会以为系统出错。

**3. 提供「双向高亮」**

- 点侧栏批语 → 正文对应段闪烁
- 点段角标 → 侧栏对应批语高亮

这是用户真正想要的交互。

## 五、工作量与风险

### 5.1 工时估算

| 步骤 | 工时 | 风险 |
|:---|:---:|:---|
| 重新提取批语补坐标 | 1 h | 低（脚本框架已有） |
| 重建正文行坐标表 | 1 h | 中（跨页段落拼接） |
| 锚定匹配 | 1 h | 中（碎行问题） |
| 前端角标 + 展开 | 2 h | 低 |
| 验证 + 文档 | 1 h | — |
| **合计** | **~6 h** | |

### 5.2 主要风险

| # | 风险 | 缓解 |
|:---|:---|:---|
| 1 | **碎行导致段内位置错误** | 只做段级，不做字符级 |
| 2 | **32% 批语无法定位** | 明确标注「位置未定」，不隐藏 |
| 3 | **重新提取可能引入新错误** | 保留现有 `pizhu.jsonl` 为基线，追加字段而非替换 |
| 4 | 跨页段落归属 | 用段落文本匹配而非纯 y 排序 |

## 六、如果不做，有什么替代方案

**低成本替代（0.5 小时）**：

侧栏批语**按 PDF 页码排序**（已有 `page` 字段），阅读时可以：

```
侧栏显示：
  p.2087  文有宾主，不可误…
  p.2090  总是勉强。
  p.2090  只用此一句，便入后文。
```

用户看到页码，翻到正文对应页区域自己找 —— 比完全无序好，但不如角标直观。

---

## 七、最终建议

**建议做方案 A（段落级锚定）**，理由：

1. **68% 的覆盖率已经很有价值** —— 三分之二的批语能直接跳到正文位置
2. **技术路径清晰** —— y 坐标对齐是排印规则决定的，不是启发式猜测
3. **风险可控** —— 明确标注未定位的 32%，不做错误映射
4. **工时合理** —— 约 6 小时，且可分阶段交付（先补数据验证，再做前端）

**不建议做方案 B（字符级）** —— 双行夹区的碎行问题会导致 50% 的错误定位，
比不做更糟。

## 八、待确认

如果要做，需要确认：

1. **角标样式**：段落右上角小圆点 ●N 还是行内上标 ¹²³？
2. **多批语同段**：一个段落有多条批语（如第50段有 5 条）→ 显示 ●5 聚合，还是全部展开？
3. **未定位批语**：留侧栏并标注「位置未定」是否可接受？
