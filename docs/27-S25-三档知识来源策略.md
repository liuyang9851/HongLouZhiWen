# S25 · 三档知识来源策略：不再一律「语料中未找到」

> 日期：2026-10-24
> 反馈：「对于此类问题，要保证在没有携带原文时自行尝试检索可能上下文，
>        如果问题本身不太可能用该方法，则由保底的模型自身知识做回答」

---

## 一、问题复现

### 1.1 用户提问

> 程高本和脂批本前八十回最大的区别有哪些？

### 1.2 旧回答（错误）

> 本次检索到的语料片段中，**没有直接论述**"程高本与脂批本前八十回差异"的内容。
> 5 条片段均为零散的脂批、回前批或回末总评，没有一条是在做版本比对，
> 因此**无法据此列出"最大区别"**。按规则，这里明确说：**语料中未找到。**

### 1.3 诊断：检索其实做了，但问题性质不同

实测检索结果：

```
改写: 程高本和脂批本前八十回最大的区别有哪些（无扩展）
kw命中=30  vec候选=30  graph=0

召回 8 条：
  [1] 第106回 [癸酉本] 甄贾宝玉遭遇雷同…   ← 后28回
  [2] 第37回 [脂批大全] 注:蒙戚二本把己庚的37回回前批…  ← 零散批语注
  [3] 第79回 [抚琴居校本] 总评：作诔后…    ← 回末总评
  [4] 第36回 [脂批大全] 注:蒙戚二本把己庚的回前批…  ← 零散批语注
  [5] 第67回 [正文:fuqinju] 好歹也罢咧！…   ← 正文
  ...
```

**根因**：这是**版本学的元知识问题**，语料里本来就没有「专门论述版本差异」的段落。
检索只能召回零散的脂批和正文，模型按「片段没有就说未找到」的规则回答 —— 规则没错，但**策略错了**。

**这类问题正该用模型自身知识回答。**

---

## 二、三档知识来源策略

```
用户提问
  ↓
① 检索（尝试召回上下文）
  ↓
② 判定问题类型 + 检索质量 → 三档分流
  ├─ 档1「语料充分」     → 基于片段回答 + 引用（原行为）
  ├─ 档2「元知识型」     → 模型自身知识兜底 + 明确标注
  ├─ 档2b「精确统计型」  → 不猜数字，引导用 🔬 自定义查询
  └─ 档3「超出范围」     → 软拒答（原行为）
```

### 2.1 判定表

| 检索结果 | 问题类型 | 策略 |
|:---|:---|:---|
| ≥3 条片段 | 普通问题 | `corpus` — 基于片段回答 |
| ≥3 条片段 | 元知识型 | `knowledge_plus_corpus` — 通识为主 + 片段佐证 |
| ≥3 条片段 | 精确统计型 | `count` — 引导用自定义查询 |
| 无片段 | 元知识型 | `knowledge` — **纯模型知识兜底** |
| 无片段 | 精确统计型 | `count` — 引导用自定义查询 |
| 无片段 | 超范围 | `refuse` — 软拒答 |

### 2.2 元知识型问题识别

```python
META_KNOWLEDGE_PAT = _re.compile(
    r"(版本|程高本|程甲本|程乙本|脂本|脂评本|庚辰本|甲戌本|己卯本|蒙府本|戚序本|"
    r"杨藏本|列藏本|舒序本|梦稿本|郑藏本|"
    r"区别|差异|不同|对比|比较|异同|"
    r"为什么|原因|为何|何以|"
    r"意义|价值|地位|影响|评价|看法|解读|理解|赏析|艺术|手法|风格|"
    r"主题|主旨|思想|内涵|寓意|象征|隐喻|伏笔|草蛇灰线|"
    r"续书|后四十回|高鹗|程伟元|"
    r"红学|考证|探佚|脂砚斋是谁|曹雪芹|作者|成书|流传|"
    r"总结|概括|概述|梳理|归纳)"
)
```

### 2.3 精确统计型问题识别（新增）

**为什么单独一档**：计数问题**绝不能**用模型知识猜数字。

```python
COUNT_Q_PAT = _re.compile(
    r"(出现了?(几次|多少次|多少个)|一共(有)?(几次|多少)|"
    r"频次|频率|次数|多少字|多少个字|字符数|字数是多少|"
    r"排名|前几|最多|最少|统计)"
)
```

### 2.4 超出范围识别

```python
OUT_OF_SCOPE_PAT = _re.compile(
    r"(三国|水浒|西游|金瓶梅|聊斋|论语|诗经|唐诗|宋词|"
    r"相对论|量子|编程|python|java|股票|基金|天气|"
    r"我爱你|你是谁|你叫什么|讲个笑话|写首诗)"
)
```

## 三、实现

### 3.1 核心函数

```python
def classify_question(question, n_contexts, n_high=0) -> str:
    """
    返回: 'corpus' | 'knowledge' | 'knowledge_plus_corpus'
          | 'count' | 'refuse'
    """
    if OUT_OF_SCOPE_PAT.search(q):
        return "refuse"
    if is_count_question(q):
        return "count"                      # 计数绝不靠猜
    if n_contexts >= 3:
        if META_KNOWLEDGE_PAT.search(q):
            return "knowledge_plus_corpus"
        return "corpus"
    if META_KNOWLEDGE_PAT.search(q):
        return "knowledge"                  # ← 关键：无检索时兜底
    return "refuse"
```

### 3.2 注入 prompt（两种模式各一段）

**`knowledge` 模式**（纯通识兜底）：

```
【关于「模型自身知识」兜底模式】
当系统告诉你「本次检索未找到直接相关的语料」时，说明这是该用通识知识回答的问题。
你必须：
1. 直接回答，不要再说"语料中未找到"就结束
2. 开头用一句话标注来源：
   「以下内容基于通识知识，非本次检索到的原文，供参考：」
3. 回答具体、准确、有信息量
4. 涉及具体原文引用时，若不确定就说明「具体回次需核对原文」
5. 结尾提示：可查阅研究资料或具体回次原文验证
绝对禁止：把通识知识伪装成"原文如此"
```

**`count` 模式**（精确统计引导）：

```
【关于「精确统计」问题】
用户问的是需要精确计数的问题。

你不能用通识知识猜测数字，也不能说"无法给出"就结束。

你的回答必须：
1. 说明为什么不能靠检索回答（Top-K 只覆盖片段）
2. 告诉用户正确做法：点输入框左侧的 🔬 按钮（自定义查询）
3. 若片段里有可参考的局部数字，可给出并标注"仅本次片段"
4. 绝对不要编造全书精确数字
```

### 3.3 修改 system prompt 第 1 条

**旧**：
```
1. 必须基于提供的【语料片段】回答。片段里没有的内容，明确说"语料中未找到"，绝不编造。
```

**新**：
```
1. 优先基于提供的【语料片段】回答，并标注引用编号，绝不编造原文。
   但若用户消息里出现【检索说明】标注"未找到直接相关语料"，
   则按「模型自身知识兜底模式」的规则用通识知识回答，
   并明确标注「以下基于通识知识，非原文」。
```

### 3.4 两条链路都改

| 端点 | 改动 |
|:---|:---|
| `/chat` | 无检索时按三档分流，不再一律拒答 |
| `/chat/stream` | **同上**（前端实际用的就是这条，容易漏改） |

## 四、效果

### 4.1 修复后

```
Q: 程高本和脂批本前八十回最大的区别有哪些？

A: 以下内容基于通识知识，非本次检索到的原文，供参考：

   ## 程高本与脂评本（前八十回）的主要区别
   1. 回目与文字规模 …
   2. 最著名的文字改动：尤三姐 …
   3. 结局与人物命运 …
   4. 具体情节差异举例 …
   5. 批语的有无 …

   关于本次检索片段：所给片段多来自癸酉本（第91、92、106、108回）
   与抚琴居本第67回，与"程高本对比"这一版本学问题不直接对应，
   故未作牵强引用。

   延伸提示：可对照阅读庚辰本与程乙本同一回（如第64、67、77回）的异文
```

**从「未找到」变成有价值、有信息量、且诚实标注来源的回答。**

### 4.2 「之」字问题

```
Q: 全文出现了几次「之」字？

A: 这是需要精确计数的问题，不能靠片段检索回答。
   为什么不能靠检索回答：本系统每次只取若干片段（Top-K），
   本次片段仅覆盖第12、16、18、67、75回的部分文字，无法代表全書…
   → 请点 🔬 按钮使用自定义查询
```

**没有编造数字，而是引导到正确的工具。**

## 五、附带修复

### 5.1 主观拒答文案不对

`SUBJECTIVE_REPLY` 原文案是「这是一个主观判断/假设性问题…而『谁更伟大』『你会选谁』这类问题…」
—— 但被「三国演义里诸葛亮是谁」这种**跨作品事实问题**复用了，文案完全对不上。

**修法**：改为通用表述：

```
这个问题超出了《红楼梦》语料可以回答的范围
（可能是跨作品、纯主观、或与本书无关的话题）。

本系统的定位是「基于语料的可追溯问答」——每个结论都能落到原文出处。
超出本书范围的问题没有语料依据，硬答只会变成编造。
```

## 七、教训

| # | 教训 |
|:---|:---|
| 1 | **「没有检索到」≠「无法回答」**。RAG 系统的边界不是语料边界，而是「语料 + 模型知识」的并集。一律拒答等于放弃模型一半能力。 |
| 2 | **拒答必须是「有理由的拒答」**。要区分「超出本书范围」和「本书没有系统论述但属常识范畴」。 |
| 3 | **标注来源比不标注更重要**。用通识知识回答时，必须让用户知道「这不是原文」。否则等于把幻觉合法化。 |
| 4 | **精确统计绝不能靠模型猜**。这类问题要用工具算，模型只负责说明「该怎么算」。 |
| 5 | **两条链路都要改**。`/chat` 和 `/chat/stream` 是两份独立代码，改一处容易漏另一处。 |
