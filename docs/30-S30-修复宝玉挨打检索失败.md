# S30 · 修复「宝玉为什么挨打」检索失败

> 日期：2026-10-27
> 用户反馈：问「宝玉为什么挨打？」，AI 回答「语料中没有检索到与『宝玉为什么挨打？』直接相关的内容」

---

## 一、问题严重性

「宝玉挨打」是《红楼梦》**第33回的核心情节**（回目：手足耽耽小动唇舌 不肖种种大遭笞挞），
是全书最重要的冲突场面之一，**绝对不该检索不到**。

系统却答「语料中没有检索到相关内容」—— 这是明确的 bug。

---

## 二、根因：两个独立的「泛化词误用」

排查发现是**两处**同类错误叠加，都是「把泛化词当成了具体触发词」。

### 2.1 错误①：检索改写过度泛化

`backend/app.py` 原代码：

```python
REWRITE_RULES = [
    # ❌ 只要问题含「为什么」，就注入这批词
    (("为什么", "为何", "原因", "缘由"),
     ["进", "入", "到", "接", "送", "投", "归", "缘由"]),
    ...
]
```

这批「进/入/到/接/送/投/归」本是给「黛玉为什么**进贾府**」写的，
但触发词只写了「为什么」，于是**所有含「为什么」的问题都被注入同一批无关词**。

**实测污染范围**：

| 问题 | 改写后的检索词 | Top-1 召回 |
|:---|:---|:---|
| 宝玉为什么挨打？ | 入 到 归 投 接 缘由 | **第67回** ❌ |
| 黛玉为什么进贾府？ | 入 到 到了都中 外祖母 弃舟登岸 归 | 第3回 ✅ |
| 宝钗为什么搬出大观园？ | 入 到 归 投 接 缘由 | **第67回** ❌ |
| 晴雯为什么被撵？ | 入 到 归 投 接 缘由 | **第67回** ❌ |

**四个问题里三个被带偏到同一回。**

### 2.2 错误②：知识兜底判定误伤

`META_KNOWLEDGE_PAT` 原正则把「为什么/原因/为何/何以」也包含进去了：

```python
META_KNOWLEDGE_PAT = _re.compile(
    r"(版本|程高本|...|"
    r"为什么|原因|为何|何以|"      # ❌ 这里
    r"意义|价值|地位|影响|评价|...)"
)
```

判定逻辑：

```python
if n_contexts >= 3:
    if META_KNOWLEDGE_PAT.search(q):
        return "knowledge_plus_corpus"   # → 注入「请以通识知识为主体回答」
    return "corpus"
```

于是「宝玉为什么挨打」被判定为「元知识型问题」，
即使检索回了第33回原文，也被强制标注：

> **以下内容基于通识知识，非本次检索到的原文，供参考**

**这是错误标注** —— 原文就在片段里，不该说成通识。

---

## 三、修复

### 3.1 修复①：改写规则去掉泛化触发

**删除**了「为什么」这条规则，改按**具体情节**建锚点：

```python
REWRITE_RULES = [
    # ---- 情节锚点：现代口语 → 原文用词 ----
    # 「宝玉挨打」= 第33回
    # ⚠️ 回目写「大遭笞挞」，但**正文里没有「笞挞」二字**
    #    （正文用的是「板子」「打死」「大板」「着实打死」）
    #    而倒排索引只对正文建，不含回目 → 扩展词必须用正文真实用词。
    (("挨打", "被打", "挨了打", "打了一顿", "毒打"),
     ["板子", "打死", "着实打死", "大板", "棍", "动弹不得"]),

    # 「被撵」= 撵出去 / 逐出
    (("被撵", "撵出去", "赶出去", "被赶", "逐出"),
     ["撵出去", "撵了", "逐出", "打发出去", "撵走"]),

    # 「抄检大观园」= 第74回
    (("抄检", "搜检", "查抄"),
     ["抄检大观园", "查抄", "搜检", "绣春囊", "王善保家的"]),

    # 「进贾府」必须出现具体词，不能只凭「为什么」
    (("进贾府", "进荣府", "进京", "投奔", "初进荣国府"),
     ["到了都中", "进入神京", "弃舟登岸", "外祖母", "轿子"]),
    ...
]
```

### 3.2 关键发现：「笞挞」不在正文里

排查中发现一个**重要细节**：

```
chunks.jsonl 中含「笞挞」的 8 处 —— 全部在 huimu（回目）字段
                          正文 text 字段：0 处
```

第33回正文的真实用词：

| 词 | 次数 |
|:---|---:|
| 打 | 31 |
| 宝玉 | — |
| 板子 | 3 |
| 打死 | 5 |
| 着实打死 | 1 |
| 笞 | 1（「笞打」） |

**而倒排索引只对 `c["text"]` 建，不含回目。**
所以扩展词若用「笞挞」，必然 0 命中。

> **这解释了为什么第一版修复（用「笞挞」做扩展词）只让第33回排到第二** ——
> 当时真正起作用的只有「板子」一个词。

### 3.3 修复②：META 正则去掉「为什么」

```python
# ⚠️ 设计教训（S30）：
#   「为什么」是**问题形式**，不是**问题领域**。
#   问「宝玉为什么挨打」是情节问题（语料里有答案），
#   问「为什么后40回争议大」才是元知识问题（语料里没有）。
#   所以把「为什么/原因/为何」从本正则删除，
#   改由「n_contexts 是否充足」来判断。
META_KNOWLEDGE_PAT = _re.compile(
    r"(版本比较|版本区别|程高本|程甲本|程乙本|脂本|...|"
    r"区别|差异|异同|版本对比|"
    r"文学史|学术史|"
    r"意义|价值|地位|影响|评价|看法|赏析|艺术|手法|风格|"
    r"主题|主旨|思想|内涵|寓意|象征|隐喻|伏笔|草蛇灰线|"
    r"续书|后四十回|高鹗|程伟元|"
    r"红学|考证|探佚|脂砚斋是谁|曹雪芹|作者|成书|流传|"
    r"总结|概括|概述|梳理|归纳)"
)
```

### 3.4 修复③：强化提示词

```python
【回答规则】
1. **必须**基于提供的【语料片段】回答，并标注引用编号，绝不编造原文。

   ⚠️ 只有在检索结果**完全为空**时（用户消息里出现【检索说明】且明确写着
   "未找到直接相关语料"），才可以按「模型自身知识兜底模式」用通识回答，
   并必须**在开头**标注「以下基于通识知识，非原文」。

   **若片段非空（哪怕只有部分相关），绝不能说"以通识知识为主体""以下基于通识"** ——
   必须先从片段里找依据、给引用，再补充解释。
```

## 五、两个错误模式的共同点

| | 错误① 改写规则 | 错误② META 正则 |
|:---|:---|:---|
| 触发词 | `为什么` | `为什么\|原因\|为何` |
| 本意 | 处理「黛玉为什么进贾府」 | 处理「为什么后40回争议大」 |
| 实际后果 | 所有原因类问题被注入无关词 | 所有原因类问题被标"通识" |
| 本质 | **泛化词当具体触发词** | 同上 |

**共同教训**：

> **「为什么」是提问形式，不是内容领域。**
> 任何基于「问题形式词」做的规则分流，都会误伤大量具体问题。
> 判定应该基于**内容特征**（是否含版本名、是否含情节词），而不是**句式特征**。

## 六、附带发现

### 6.1 「笞挞」只在回目里

这是一个**索引与语料不一致**的问题，值得记录：

```
回目（huimu）：第33回 手足耽耽小动唇舌 不肖种种大遭笞挞   ← 有「笞挞」
正文（text）：  ...举起大板打了十来下...              ← 没有「笞挞」
索引（hlm_terms）：只对 text 建，不含 huimu
```

**影响**：用户若用回目里的词（如「笞挞」「不肖种种」）检索，会 0 命中。

**建议**（未实施）：把 `huimu` 也纳入倒排索引，或单独建一个回目索引。

### 6.2 第67回仍是高频干扰项

修复后第33回排第一，但第67回仍在第2位。

原因：关键词打分没有 IDF 加权

```python
scores[cid] = scores.get(cid, 0) + 1.0 + min(tf, 2) * 0.1
#                                    ↑ 所有 bigram 权重相同
```

`宝玉` df=596（几乎处处有），`打死` df=24（稀有），但两者权重都是 1.0。

**建议**（未实施）：改成 IDF 加权
```python
idf = log(N / df)
scores[cid] += idf * (1.0 + min(tf, 2) * 0.1)
```

`hlm_terms` 表里已有 `p:df` 字段，改造成本低。
