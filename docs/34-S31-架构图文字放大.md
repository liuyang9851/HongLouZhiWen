# S31 · 欢迎页「程序架构」图文字放大

> 日期：2026-10-26
> 需求：「欢迎页的程序架构的图中的文字比较小，我希望也能放大一些」

---

## 一、问题

架构图是 **SVG**（不是 Canvas），`viewBox="0 0 900 720"`，
文字用 viewBox 单位标注，渲染时 `max-width: 900px` → 基本 **1:1**。

| 元素 | 原字号 |
|:---|---:|
| 方框标题 `txt()` 默认 | 11px |
| 说明文字 `mono()` 默认 | 9.5px |
| 部分密集区域 | 8 / 8.5px |

投影时 9.5px 确实偏小。

---

## 二、关键约束：不能无脑放大

放大字号前必须先摸清布局约束，否则文字会互相压住：

### 约束① 行距是硬编码的 14 单位

```javascript
${mono(144, 172, '三版本正文 167.8 万字', 9.5)}   // y=172
${mono(144, 186, '三源脂批 12,457 条', 9.5)}      // y=186  → 间距 14
${mono(144, 200, '/hlm/manifest', 9.5)}           // y=200  → 间距 14
```

**字号上限 ≈ 11.5**（14 ÷ 1.2 ≈ 11.7），超过就会行间重叠。

### 约束② 部分方框只有 160 单位宽

`hlm_chunks` / `hlm_vectors` 等窄框内塞了 4 行文字，
最宽一行「personfreq 41 · cooccur 10,742」30 个字符。

---

## 三、方案：温和放大字号 + 提高渲染宽度

单靠字号放大受行距限制，所以**两条腿走路**：

### ① 字号统一 ×1.15

| 原字号 | 放大后 | 处数 |
|---:|---:|---:|
| 8.0 | 9.0 | 1 |
| 8.5 | 10.0 | 19 |
| 9.0 | 10.5 | 6 |
| 9.5 | 11.0 | 13 |
| 10.0 | 11.5 | 9 |
| 10.5 | 12.0 | 13 |
| 11.0 | 12.5 | 4 |
| 11.5 | 13.0 | 4 |
| 12.0 | 14.0 | 2 |
| 12.5 | 14.5 | 3 |

合计 **74 处**（含 2 个函数默认值）。

最大字号 11（说明）/ 14.5（大标题），行距 14 → 比例 1.27，安全。

### ② 渲染宽度 900px → 1024px

容器 `.hp-arch-wrap` 可用宽度约 995px，原来被 `max-width:900px` 卡住。
提到 1024 后，SVG 会撑满容器，**整体再放大约 1.10 倍**。

### 合计视觉放大

```
1.15（字号）× 1.10（渲染）= 约 1.27 倍
```

| 元素 | 放大前 | 放大后（实际渲染）|
|:---|---:|---:|
| 方框标题 | 11px | 约 **15px** |
| 说明文字 | 9.5px | 约 **12.5px** |
| 密集区小字 | 8.5px | 约 **11px** |

---

## 四、遇到并修复的 2 个脚本 bug

### bug1：正则跨行匹配，把注释当字符串

`[^'"\\]` 会匹配换行符，导致从某个引号一路吃到很远的引号，
把注释里的 `dfs.blocksize = 134217728` 当成字号。

```
134217728.0px → 154350387.0px  ×1     ← 明显不对
```

**修法**：字符类排除换行 `[^'"\\\n]`。

### bug2：`(size )= ` 误匹配 `blocksize = `

匹配函数默认参数的正则 `(size )= ` 没有词边界，
把注释里的 **block**`size = 134217728` 命中了。

**修法**：加词边界 `(\bsize)\s*=\s*([\d.]+)`。

> 这两个 bug 都是「正则写得太宽松」导致误伤注释。教训：
> **批量改代码前，先 dry-run 看改动清单，异常值一眼能看出来。**

## 五、顺带修正的过期数据

| 位置 | 旧值 | 新值 |
|:---|:---|:---|
| 架构图「L3 图谱召回」 | 120 节点 / 253 边 | **350 节点 / 674 边** |
| 左侧栏「人物」迷你统计 | 120 | **350**（改为动态读 `/api/graph`） |

侧栏那个还顺手改了实现：原来取 `manifest.stats_summary.graph_nodes`（静态值），
现在直接调 `/api/graph` 拿 `n_nodes`，**以后不会再过期**。

```javascript
// 原来
$('#ms-nodes').textContent = mani.stats_summary.graph_nodes;

// 现在
const gg = await api('/api/graph');
$('#ms-nodes').textContent = fmt(gg.n_nodes || mani.stats_summary.graph_nodes);
```

## 八、如果还想更大

当前已接近行距上限。要继续放大只能**同时改布局**：

1. 把行距从 14 提到 17（需要调整 ~60 个 y 坐标）
2. 把所有方框高度 +20%
3. `viewBox` 高度从 720 提到 860

这是结构性改动，风险较高。如需继续放大，建议走这条路，
而不是单纯调字号 —— 否则一定重叠。
