# S19 · 诊断：为什么问「贾宝玉的丫鬟有谁」只答出袭人一人

> 日期：2026-10-24
> 用户反馈：「模型最终给出的回答是只有袭人一人，这显然是不合常理的，为什么？」

---

## 一、结论

**这不是 bug，是「聚合型问题」与「Top-K 检索」的范式不匹配。**

模型诚实遵守了「片段里没有就说没有」的规则；
检索也确实按查询召回了相关段落；
**但《红楼梦》从来没有集中交代过「宝玉的丫鬟名单」—— 这些人分散在 17 个回次里。**

Top-K 检索只能拿到 5 个片段，装不下分散在全书的信息。

---

## 二、完整证据链

### 2.1 复现（可验证）

```bash
POST /chat {"question":"贾宝玉的丫鬟有谁？"}
```

实际回答：

> 根据语料，贾宝玉的丫鬟可确认的有：
> - **袭人**：原为贾母之婢，本名珍珠…[1][2]
> - **晴雯**：语料中未出现，无法确认。
> - **秋纹、碧痕等**：语料中未出现，无法确认。
>
> 语料中明确提到的宝玉丫鬟只有袭人一人，其余（如晴雯、秋纹等）在提供的片段中未找到。

引用只有 5 个片段：第3回(×2)、第8回、第67回(×2)。

### 2.2 关键事实：《红楼梦》没有「丫鬟名单」段落

实测各丫鬟在抚琴居本首次出现的回次：

| 丫鬟 | 首次出现 | 丫鬟 | 首次出现 |
|:---|:---:|:---|:---:|
| 袭人 | **第 3 回** | 檀云 | 第 23 回 |
| 晴雯 | **第 5 回** | 绮霰 | 第 20 回 |
| 麝月 | **第 5 回** | 紫绡 | 第 27 回 |
| 媚人 | 第 5 回 | 媚人 | 第 5 回 |
| 茜雪 | 第 7 回 | 可人 | 第 28 回 |
| 秋纹 | 第 19 回 | 良儿 | 第 52 回 |
| 碧痕 | 第 20 回 | 坠儿 | 第 26 回 |
| 四儿 | 第 21 回 | 芳官 | 第 54 回 |
| 小红 | 第 24 回 | 春燕 | 第 59 回 |

**分散在 17 个回次，跨 56 回。** 没有任何一段文字说「宝玉的丫鬟有：袭人、晴雯、麝月…」。

### 2.3 唯一接近「名单」的段落，也只有袭人

第3回 段22-24（检索 Top-1，554 字）是全书最接近「交代宝玉丫鬟配置」的地方：

> 宝玉之乳母李嬷嬷，**并大丫鬟名唤袭人者**，陪侍在外面大床上。
> 原来这袭人亦是贾母之婢，本名珍珠。贾母因溺爱宝玉…遂与了宝玉。

实测这段 554 字里：

| 名字 | 出现 |
|:---|:---:|
| 袭人 | ✅ |
| 李嬷嬷 | ✅ |
| 珍珠（袭人本名） | ✅ |
| 鹦哥（黛玉的丫鬟） | ✅ |
| 雪雁（黛玉的丫鬟） | ✅ |
| **晴雯** | ❌ |
| **麝月** | ❌ |
| **秋纹** | ❌ |
| **碧痕** | ❌ |

**所以检索没有错，chunk 里确实只有袭人。模型答「只有袭人」是基于给的材料的正确回答。**

### 2.4 查询改写也有误导

```
改写后：贾宝玉的丫鬟有谁 丫头 丫鬟 大丫鬟 小丫头 袭人 雪雁 鹦哥
                                                    ↑     ↑
                                              鹦哥是黛玉的丫鬟
```

`鹦哥` 是贾母给**黛玉**的二等丫头，不是宝玉的。
改名把「鹦哥」加进去，反而把检索引向了黛玉的段落（第8回雪雁那一条）。

同时**漏了真正相关的词**：「李嬷嬷」「珍珠」「怡红院」「屋里人」。

## 三、四层原因

| 层 | 问题 | 严重度 |
|:---|:---|:---:|
| **① 数据本质** | 名单散布 17 个回次，无集中段落 | 🔴 根本原因 |
| **② 检索范式** | Top-K 只取 5 段，装不下分散信息 | 🔴 根本原因 |
| **③ 查询改写** | 加了错的「鹦哥」，漏了「李嬷嬷/珍珠」 | 🟡 加重问题 |
| **④ 回答规则** | 「片段里没有就说没有」—— 规则正确，但让缺陷暴露成「只有一人」的答案 | 🟢 不是问题 |

---

## 四、为什么这不是「模型幻觉」或「代码 bug」

| 猜测 | 实际 |
|:---|:---|
| 模型偷懒？ | 否。它明确标注了「语料中未出现」「无法确认」 |
| 数据缺失？ | 否。17 个丫鬟在语料里都有，只是分散 |
| 检索坏了？ | 否。Top-1 就是最相关的第3回段落 |
| chunk 被截断了？ | 否。`build_messages` 用完整 `c['text']`，不是 snippet |

**真正的问题：问的是「全集」，检索给的是「Top-K」。范式不匹配。**

## 五、可行的解决方案（按性价比排序）

### 方案 A：聚合型问题走「统计/图谱」通道 ⭐ 推荐

系统里已有现成能力但没接上：

| 已有能力 | 现状 | 可用来做什么 |
|:---|:---|:---|
| `hlm_wordfreq`（133,673 行） | 只用于统计界面 | 找与「宝玉」高频共现的人物名 |
| `personfreq`（41 人物） | 只用于统计界面 | 人物出现次数 |
| `cooccur`（10,742 组） | 只用于图谱 | 人物共现关系 |
| 人物关系图谱 | 已实现 | 宝玉 → 丫鬟 的关系边 |

**做法**：
1. 识别「名单型问题」：含「有谁/有哪些/都是谁/名单/几人」等
2. 查图谱：找 `宝玉` 的关系边中 label 含「丫鬟/丫头」的节点
3. 用图谱结果补充检索，或直接作为答案骨架
4. 每个名字回原文找证据

**工作量**：4~6 小时
**效果**：能答出完整名单（图谱里有多少算多少）

### 方案 B：扩大 Top-K + 多轮检索

```python
# 名单型问题：先宽召回，再按人名聚合
topk = 30 if is_list_question else 5
```

**工作量**：1 小时
**效果**：能捞到更多名字，但不保证完整（30 段仍不够覆盖 56 回）

### 方案 C：诚实降级 ⭐ 成本最低

**回答改成**：

> 《红楼梦》没有集中交代宝玉的丫鬟名单，这些人物分散在全书。
> 本期检索到的片段中提到的是：**袭人**（第3回）。
> 其他常见丫鬟（晴雯、麝月、秋纹、碧痕等）出现在第5、19、20回等处，
> 但本次检索未覆盖 —— 建议查看「人物关系」页面，或分别提问。

**工作量**：0.5 小时（只改 prompt + 加一条「分散性事实」提示）
**效果**：用户知道「不是系统漏了，是这问题本身需要跨全书检索」

### 方案 D：预建「人物-身份」索引

离线跑一遍：对 41 个人物，用 co-occurrence + 人工规则标注身份（丫鬟/主子/亲戚…）。

**工作量**：8+ 小时
**效果**：最准，但工程量大

## 六、我的建议

**短期先做 C（0.5h），中期做 A（4-6h）。**

理由：

1. **C 立刻止血** —— 用户不会再看到「只有袭人一人」这种答案
2. **A 是正道** —— 系统已有图谱和统计能力，只是没被问答用到
3. **B 是补丁** —— 扩大 Top-K 只是撞运气，不解决范式问题
4. **D 太重** —— 41 个人物手工标注不值得

### C 的具体改法

在 `SYSTEM_PROMPT` 里加一条：

```
【关于"全集型"问题】
如果问题问的是「有哪些/都有谁/名单」这类全集，
而提供的片段只覆盖其中一部分，必须：
  1. 明确说明「《红楼梦》未集中交代，人物分散在全书各处」
  2. 列出片段中能确认的
  3. 说明本次检索范围有限，不代表全书只有这些
  4. 建议用户查看「人物关系」页面或分别提问
不要用「只有X一人」这种结论性表述。
```

### A 的具体改法

```
用户问「宝玉的丫鬟有谁」
  ↓ 识别为名单型
查图谱：宝玉 --[丫鬟]--> ?
  命中：袭人、晴雯、麝月、秋纹、碧痕…
  ↓ 对每个名字，检索其证据段落
组装答案：名字 + 出处
```
