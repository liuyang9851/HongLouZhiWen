## 二、关键决策：视频不入库

GitHub 单文件上限 **100 MB**，视频 115 MB 放不进去。

所以**没有**把视频复制到 `web/public/`，而是让本地 Node 服务从磁盘原路径**流式输出**：

```
浏览器 <video src="/api/intro-video">
        ↓
web/server.js  fs.createReadStream(视频原路径)
        ↓
D:\...\视频\film\交付\红楼智问_1080p.mp4
```

好处：
- 仓库不膨胀（视频 0 字节入库）
- 不重复占用磁盘
- 换视频只需换文件或改环境变量，不用动代码

路径可覆盖：

```bash
HLM_INTRO_VIDEO="D:\其他路径\video.mp4" node server.js
```

## 三、HTTP Range 支持（必须）

视频流必须支持 Range，否则：
- 无法拖动进度条
- 无法边下边播（浏览器要下载完 115 MB 才播）

实现（`web/server.js`）：

```javascript
function serveIntroVideo(req, res) {
  const total = fs.statSync(INTRO_VIDEO).size;
  const range = req.headers.range;

  if (!range) {                              // 无 Range → 200 全量
    res.writeHead(200, { 'Content-Type': 'video/mp4',
                         'Accept-Ranges': 'bytes',
                         'Content-Length': total });
    return fs.createReadStream(INTRO_VIDEO).pipe(res);
  }

  // "bytes=start-end" → 206
  const m = /^bytes=(\d*)-(\d*)$/.exec(range.trim());
  ...
  res.writeHead(206, {
    'Content-Range': `bytes ${start}-${end}/${total}`,
    'Content-Length': end - start + 1,
    ...
  });
  fs.createReadStream(INTRO_VIDEO, { start, end }).pipe(res);
}
```

**实测**：

| 请求 | 响应 |
|:---|:---|
| `Range: bytes=0-1023` | `206` + `Content-Range: bytes 0-1023/120632766` |
| `Range: bytes=60000000-60000999` | `206` + 中段区间（模拟拖动） |
| 无 Range（HEAD） | `200` + `Content-Length: 120632766` |

另外还有 `GET /api/intro-video/info` 返回 `{exists, size, mb, path}`，供前端提示。

## 四、前端实现

### 4.2 弹窗

点击创建 `modal-mask` + `<video controls autoplay>`：

```
┌──────────────────────────────────────────┐
│ 🎬 红楼智问 · 项目介绍              ✕    │
├──────────────────────────────────────────┤
│                                          │
│            <video controls>              │
│                                          │
├──────────────────────────────────────────┤
│ 4 分 32 秒                               │
└──────────────────────────────────────────┘
```

三种关闭方式：

| 方式 | 实现 |
|:---|:---|
| 点 ✕ | `.vid-x.onclick = close` |
| 按 Esc | `document.addEventListener('keydown', onKey)` |
| 点遮罩 | `if (e.target === mask) close()` |

`close()` 会 **销毁 video**（`pause()` + `removeAttribute('src')` + `load()`），
避免 115 MB 的流在后台继续下载。

### 4.3 文件缺失时的提示

打开时先查 `/api/intro-video/info`，不存在就显示：

> ⚠️ 未找到视频文件
> `D:\...\视频\film\交付\红楼智问_1080p.mp4`

而不是让用户对着黑屏猜。

## 五、顺带修复的两个问题

### 5.1 首页白屏：`$ is not defined`

我在 `page_home.js` 里写了 `$('#btnIntroVideo')`，但 `$` 是 `app.js` 的**模块内**辅助函数，
`page_home.js` 里没有，于是：

```
ReferenceError: $ is not defined
    at renderHome (page_home.js:389)
```

**整页渲染中断 → 白屏**。

修法：改用原生 `document.getElementById()`。
同时发现 L369 也有同样隐患（`$ ? $('#chatTextarea') : ...`），一并改掉。
现在 `page_home.js` 全文无 `$(` 调用。

### 5.2 改了代码看不到效果：ES Module 被缓存 5 分钟

`server.js` 原本对静态资源：

```javascript
'Cache-Control': ext === '.html' ? 'no-cache' : 'public, max-age=300'
```

`.js` 被缓存 5 分钟。而 `app.js` 用 `import` 引入 `page_home.js` **不带版本号**，
所以 `index.html` 的 `?v=xxx` 只对 `app.js` 生效，子模块仍是旧缓存。

排查时踩了很久：服务端返回的是新代码，浏览器却一直在跑旧版。

修法：

```javascript
'Cache-Control': (noCache || ['.html','.js','.css'].includes(ext))
  ? 'no-store, must-revalidate'
  : 'public, max-age=300'
```

`.js/.css/.html` 一律要求回源校验（ETag 仍生效，未变则 304），保证改代码即时可见。

## 九、教训

| # | 教训 |
|:---|:---|
| 1 | **大文件不要进 git**。115 MB > GitHub 100 MB 限制，改用服务端流式输出，仓库零负担。 |
| 2 | **视频必须支持 Range**。否则不能拖进度条、不能边下边播。 |
| 3 | **不同模块的辅助函数不共享**。`$()` 是 `app.js` 模块内的，`page_home.js` 用不了 —— 报错还会让整个页面白屏。 |
| 4 | **ES Module 子模块不受父模块 `?v=` 影响**。要么服务端不缓存 `.js`，要么给每个 import 加版本号。 |
| 5 | **关闭弹窗要销毁 media 元素**，否则 115 MB 的流还在后台跑。 |
