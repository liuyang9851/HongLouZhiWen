## 一、总体结构

### 1.1 单页应用（SPA）路由

采用 **hash 路由**，8 个主视图 + 若干叠加层。

```
#/home     欢迎页       🏠
#/chat     AI 问答      💬  [核心]
#/reader   原文阅读      📖
#/stats    统计信息      📊
#/graph    人物关系      ⚭
#/guiyou   癸酉本探究    🔬
#/corpus   语料版本      🗂
#/ops      系统运维      ⚙
```

路由实现（`app.js:155`）：

```javascript
const VIEWS = ['home','chat','reader','stats','graph','guiyou','corpus','ops'];
// :param 形式支持带参数，如 #/reader/78?ver=fuqinju
```

### 1.2 页面骨架

```
┌──────────────────────────────────────────────────────────┐
│  顶栏：品牌 · 模型选择器 ⚙配置 · RAG 状态灯  11780 chunk  │
├────────┬─────────────────────────────────────────────────┤
│        │                                                 │
│  左侧  │              主内容区 #stage                     │
│  导航  │         （按路由切换 8 个视图）                  │
│  rail  │                                                 │
│        │                                                 │
├────────┴─────────────────────────────────────────────────┤
│  底部：81 回 · 8,510 批语 · 120 人物                      │
└──────────────────────────────────────────────────────────┘
```

**设计要点**：左侧 rail 常驻，8 个视图共享同一顶栏/底栏。
便于用户随时在「问答 → 原文 → 统计」之间跳转（这正是 RAG 系统需要的探索动线）。

**关键元素**：

|:---|:---|:---|

| 版本说明 | `#verHint` | 当前版本描述 + 脂批来源提示 |
| 回目列表 | `#rdList` | 逐回按钮，显示回目 + 字数 |

| 本回标题 | `#rdTitle` `#rdMeta` | 回目 + 字数/段数/版本 |
| 就本回提问 | `#askThis` | 🎯 带整回上下文提问 |
| 正文容器 | `#rdScroll` `#rdPaper` | 可划选、可点击段落 |
| 脂批侧栏 | `#pzAside` | **按版本隔离**，标题随版本变 |
| 脂批列表 | `#pzBody` | 每条带版本标签 + 页码 |

**核心设计（⚠️ 重要经验）**：

1. **脂批按版本隔离**
   ```
   fuqinju   → 抚琴居脂批 + 脂批大全
   guiyouben → 癸酉本批语（后28回内嵌批/回前批/回末评）
   chenggao  → 空（删改本无脂批）→ 显示说明而非隐藏
   ```
   > **反面教材**：早期版本用 `display:none` 直接隐藏非主版本侧栏，
   > 用户以为功能坏了。正确做法是**显示说明**（"程高本是删改本，没有脂批"）。

2. **段落级提问**：单击任意段落 → 段落右上角浮出「🎯 就这段提问」

3. **划选提问**：拖选文本 → 浮层 → 带入问答

4. **跨版本对照**：同一段落在其他版本中的对应文本（`other_versions`）

5. **滚动容器必须 `min-height:0`**
   > **踩坑**：flex 子元素默认 `min-height:auto`，导致 `overflow-y:auto` 失效。
   > 8 个滚动容器都需显式加 `min-height:0`。

### ⑥ 癸酉本探究 `#/guiyou`

**文件**：`page_guiyou.js`（~430 行）+ `web/data/s22_guiyou.json`

**布局**：单列纵向滚动，8 个章节

| # | 章节 | 内容 |
|:--:|:---|:---|
| 1 | 争论是什么 | 支持方 4 条 vs 反对方 4 条（左右对照） |
| 2 | 研究方法 | 3 组对照 + 1 校验组表格 / 4 部明清小说 / 两组特征集 |
| 3 | 结果①：字/词频 | 「被」字条形图 / 句长 / 四字格 / 秩相关 / 距离+bootstrap |
| 4 | 结果②：词性 | 距离排名条 / 最近邻卡片 / 方法有效性验证条 |
| 5 | 稳健性检验 | 4 项检验卡片 |
| 6 | 结论分层 | 三层（确定 / 显著 / 不能推出）+ 综合解读 |
| 7 | **我犯的两个方法错误** | 完整交代，含错误代码片段 |
| 8 | 局限 + 可复现 | 6 条局限 + 6 个复现命令 |

**值得借鉴的三个设计**：

1. **数据来自实际跑出的 JSON**，失败时降级为内置兜底值
2. **结论必须分三层** —— 不让人把"统计显著"误读为"证明了"
   ```
   第一层 确定的事实
   第二层 统计显著但需保留（含"余弦距离给出相反结论"）
   第三层 不能从统计推出的
   ```
3. **公开自己的方法错误** —— 第 7 章专门写对照语料被污染、定位方法错误两件事
   > 这一节比结论本身更重要：说明计量研究里**数据核查比算法关键**

### 3.1 清除历史对话确认弹窗

**触发**：问答页侧栏 🗑 按钮

```
┌────────────────────────────────────┐
│  清除历史对话记录                   │
├────────────────────────────────────┤
│  将删除 12 个对话（共 32 条消息）。 │
│                                    │
│  只清除本地对话记录                 │
│  ✅ 删除：对话列表与消息内容         │
│  ✅ 删除：各版本的「上次阅读回次」   │
│  ❌ 保留：语料、索引、向量、模型配置 │
│                                    │
│  此操作不可撤销。                   │
│               [ 取消 ]  [ 确认清除 ] │
└────────────────────────────────────┘
```

**设计要点**：
1. **明确列出「删什么 / 不删什么」** —— 用户最担心误删
2. 显示影响范围（N 个对话 M 条消息）
3. 三个退出路径：取消 / 点遮罩 / ESC
4. 清除后自动建一个空对话（避免界面空白）
5. **文案必须与行为一致** —— 早期版本写"保留阅读进度"但实际清了，已修正

## 四、跨界面交互设计

这是本项目最值得借鉴的部分 —— **界面之间不是孤立的**。

```
       ┌──────────────┐
       │  原文阅读     │
       │              │
       │ ① 划选文本 ───┼──→ 带上下文跳到问答
       │ ② 点击段落 ───┼──→ 「就这段提问」
       │ ③ 就本回提问 ─┼──→ 带整回上下文
       │ ④ 脂批点击 ───┼──→ 可复制追问
       └──────┬───────┘
              │ ⑤ AI 回答的引用角标
              ↓ 跳回原文对应段落
       ┌──────────────┐
       │   AI 问答     │
       └──────┬───────┘
              │ ⑥ 统计项点击「发起提问」
              ↓
       ┌──────────────┐
       │  统计信息     │
       └──────────────┘
```

**四个方向的双向跳转**：

| 从 | 到 | 触发方式 |
|:---|:---|:---|
| 原文 → 问答 | 划选文本 / 点击段落 / 就本回提问 | 带上下文 |
| 问答 → 原文 | 点击引用角标 `[1]` | 定位到段落 |
| 统计 → 问答 | 点击统计项 | 带统计数据提问 |
| 图谱 → 问答 | 点击「🎯 问他」 | 带人物上下文提问 |

**实现关键**：上下文通过 `state.pendingContext` 传递，问答页显示为「上下文芯片」。

## 六、文件结构

```
web/public/
├── index.html                3,519 B   SPA 骨架 + 左侧导航
├── css/
│   ├── app.css               9,916 B   全局变量、布局、rail
│   ├── views.css            38,217 B   8 个视图样式
│   └── pages.css            22,180 B   欢迎页 + 癸酉本页 + 架构图
└── js/
    ├── app.js               99,276 B   主模块：路由 + 6 个视图
    ├── page_home.js         12,681 B   欢迎页（新增视图）
    ├── page_guiyou.js       25,758 B   癸酉本探究页（新增视图）
    ├── arch_diagram.js      10,034 B   SVG 架构图
    ├── chart.js             22,462 B   自研图表库（零依赖）
    ├── md.js                 7,616 B   自研 Markdown 渲染器
    ├── providers.js         11,989 B   模型配置面板
    └── rag.js                8,350 B   后端 API 封装
```

**架构选择**：**原生 ES Module，零框架**（不用 React/Vue）。

| 优点 | 缺点 |
|:---|:---|
| 无构建步骤，改完刷新即生效 | 无组件复用机制，需手动组织 |
| 打包体积小（~230 KB 源码） | 状态管理靠自己 |
| 调试直观（源码即运行代码） | 大项目会失控 |

> 对本项目规模（8 视图 / 22K 行）刚好合适。

## 七、可借鉴的设计经验

### 7.1 做得好的

| # | 经验 | 说明 |
|:--:|:---|:---|
| 1 | **强制引用溯源** | 每条结论标注 `[版本·回次·段号]`，可点击跳转。RAG 系统的信任基础 |
| 2 | **跨界面上下文传递** | 原文↔问答↔统计↔图谱 四向跳转，形成探索闭环 |
| 3 | **如实标注数据状态** | 「真实」标签、ZooKeeper 标 ⚠️、「已重解码」标签 |
| 4 | **架构图纯 SVG** | 可缩放/可打印/可搜索，零依赖 |
| 5 | **结论分三层** | 区分"确定/显著/不能推出"，避免误导 |
| 6 | **公开方法错误** | 癸酉本探究页第 7 章专门写自己踩的坑 |
| 7 | **确认弹窗列清影响** | 明确"删什么/不删什么"，而非只问"确定吗" |
| 8 | **AI 代码可审计** | 自定义查询展示生成的代码，用户可核对 |

### 7.2 踩过的坑（供参考）

| # | 坑 | 现象 | 原因 | 解法 |
|:--:|:---|:---|:---|:---|
| 1 | **flex 滚动失效** | 侧栏内容被裁切，滚轮无效 | flex 子元素 `min-height:auto` | 显式 `min-height:0` |
| 2 | **长页面无法滚动** | 新页面内容全渲染但滚不动 | `.view{height:100%;overflow:hidden}` 是为固定高度视图设计的 | 新页面单独 `height:auto + overflow:visible` |
| 3 | **模块间共享函数** | `esc is not defined` | ES module 求值顺序，宿主 `app.js` 还没赋值 | 延迟获取 `const H = () => window.__HLM__ \|\| {}` |
| 4 | **"隐藏"当"解决"** | 非主版本脂批侧栏消失，用户以为坏了 | 用 `display:none` 逃避"不同版本数据不同"的真实需求 | 改为显示说明文字 |
| 5 | **中文数字渲染错误** | 「贰」显示成生僻字「贑」 | 字体 ligature 替换 | 改用阿拉伯数字 |
| 6 | **文案与行为不符** | 弹窗说"保留阅读进度"但实际清了 | 改代码时忘了改文案 | 文案必须核对真实行为 |
| 7 | **静态资源缓存** | 改了代码浏览器还跑旧版 | 浏览器强缓存 | `?v=<timestamp>` + `no-store` |

### 7.3 界面数量与工作量参考

| 项 | 数量 |
|:---|:---|
| 主视图 | 8 个 |
| 叠加层 | 4 个（清除确认/自定义查询/证据面板/模型配置） |
| 前端代码 | ~22,000 行（12 个文件） |
| CSS | ~70,000 B（3 个文件） |
| 后端接口 | 21 个（9 Node + 12 FastAPI） |
