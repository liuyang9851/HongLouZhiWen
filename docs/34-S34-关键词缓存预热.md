# S34 · 关键词缓存预热

> 日期：2026-10-27
> 起因：S33 遗留项「无预热机制，首次提问仍要等 LLM」
> 用户确认「好的」

---

## 一、要解决什么

S33 加了缓存，但**首次提问仍然要等 LLM**（1.8~1.9s）。

而实际使用中，**首批问题高度可预测**：

| 场景 | 可预测的问题 |
|:---|:---|
| 前端示例（6 个 starter） | 用户点第一下就是这些 |
| 课堂演示/答辩 | 反复走同一批问题 |
| 常见问法 | 「宝玉挨打」「黛玉葬花」这类 |

**如果后端启动时就主动生成这些问题的关键词，用户第一次点击就能命缓存。**

---

## 二、实现

### 2.1 预热问题清单（15 个）

```python
WARMUP_QUESTIONS = [
    # ---- 前端 6 个 starter（与 app.js 的 STARTERS 保持一致）----
    "贾宝玉的丫鬟有谁？",
    "林黛玉为什么进贾府？",
    "第19回为什么批语最多？",
    "宝玉和黛玉是什么关系？",
    "「千红一窟」有什么隐喻？",
    "前80回一共多少字？",
    # ---- 常见问法（演示/答辩时容易被问）----
    "宝玉为什么挨打？",
    "晴雯为什么被撵？",
    "金钏为什么投井？",
    "黛玉葬花在第几回？",
    "通灵宝玉上的铭文是什么？",
    "宝钗扑蝶是怎么回事？",
    "刘姥姥进大观园在哪一回？",
    "贾宝玉的丫鬟有哪些",      # 无标点变体
    "宝玉和黛玉什么关系",      # 简写变体
]
```

**为什么包含变体**：S33 的缓存 key 做了标点/空白归一，
所以「贾宝玉的丫鬟有谁？」和「贾宝玉的丫鬟有哪些」是两条不同缓存（改了疑问词）。
两条都预热，覆盖更多说法。

### 2.2 后台异步执行（关键）

```python
@app.on_event("startup")
async def startup():
    ...
    # S34：后台异步预热关键词缓存（不阻塞启动）
    import asyncio as _aio
    try:
        _aio.create_task(warmup_keywords())
        log("  关键词预热任务已提交（后台执行）")
    except Exception as e:
        log(f"  关键词预热任务提交失败: {e}")
```

**为什么必须异步**：
15 个问题 × 约 1s = **15 秒**。若同步执行，后端启动要等 15 秒才能接受请求，
体验极差（前端会显示"后端未就绪"）。

用 `create_task` 丢到后台，启动立即可用，预热在后台慢慢跑。

### 2.3 智能跳过

```python
async def warmup_keywords():
    _kw_cache_load()

    if len(_kw_cache) >= len(WARMUP_QUESTIONS):
        _warmup_state["skipped"] = True
        log(f"  关键词缓存已有 {len(_kw_cache)} 条，跳过预热")
        return
```

**为什么**：缓存已落盘（S33 实现的），重启后通常还有数据。
若已足够，不必重复调 LLM（省时间 + 省 token）。

实测：重启时缓存有 8 条 < 15 条 → 继续预热，只补缺的 7 条。

### 2.4 逐条跳过已有

```python
for i, q in enumerate(WARMUP_QUESTIONS, 1):
    if _kw_cache_get(q) is not None:      # 已有则跳过
        _warmup_state["done"] = i
        continue
    try:
        kws = await gen_keywords(q, model, timeout=10.0)
        if kws:
            _kw_cache_put(q, kws)
    except Exception as e:
        log(f"    预热失败 [{q}]: {type(e).__name__}")
    _warmup_state["done"] = i
    await asyncio.sleep(0.1)              # 让出事件循环
```

**两个细节**：

1. **`await asyncio.sleep(0.1)`**
   每处理一个就让出事件循环，避免预热把 CPU 占满导致正常请求变慢。

2. **单个失败不影响整体**
   `try/except` 包在循环内，一个失败继续下一个。

### 2.5 状态可观察

```python
_warmup_state = {"running": False, "done": 0, "total": 0, "skipped": False}
```

`GET /keyword-cache/stats` 返回里带上：

```json
{
  "entries": 15,
  "warmup": {
    "running": false,
    "done": 15,
    "total": 15,

```


## 六、注意事项

### 6.1 预热问题清单需要与前端同步

`WARMUP_QUESTIONS` 前 6 条必须与 `web/public/js/app.js` 的 `STARTERS` 一致。

**当前状态**：两边手动保持一致（已核对）。

**风险**：修改前端示例问题时容易忘记改后端。

**改进方向**（未实施）：把问题清单抽成共享 JSON，
前后端都读同一个文件。

### 6.2 预热会消耗 token

15 个问题 × 约 200 token = **约 3,000 token**（只在缓存不足时跑一次）。

若频繁重启容器（如开发调试），会反复消耗。
可以用 `HLM_SKIP_WARMUP=1` 关闭（当前未实现，需要时加）。

### 6.3 预热与请求的并发

预热在后台跑，用户请求同时进来时：
- 两者都调 LLM，可能触发 API 速率限制
- 但 `await asyncio.sleep(0.1)` 已经错开了密集调用

实测无问题。

## 六点五、开关（S34b 补充）

### 环境变量

| 变量 | 默认 | 作用 |
|:---|:---|:---|
| `HLM_SKIP_WARMUP` | `0` | 设为 `1`/`true`/`yes` → **完全跳过预热** |
| `HLM_WARMUP_N` | `0` | `>0` 时只预热前 N 个问题；`0` = 全部 15 个 |

### 用法

```bash
# 开发调试：不预热（省 token）
docker run -e HLM_SKIP_WARMUP=1 ...

# 只想快速验证：只预热前 3 个
docker run -e HLM_WARMUP_N=3 ...

# 生产默认：全部预热
docker run ...
```

### 三种模式实测

| 模式 | 启动日志 | stats |
|:---|:---|:---|
| 默认 | `关键词预热任务已提交（后台执行，15 个问题）` | `enabled=True` |
| `HLM_SKIP_WARMUP=1` | `关键词预热: 已禁用（HLM_SKIP_WARMUP=1）` | `enabled=False, skipped=True, reason="HLM_SKIP_WARMUP=1"` |
| `HLM_WARMUP_N=3` | `关键词预热任务已提交（后台执行，3 个问题）` | `enabled=True, limit=3, n_questions=15` |

### stats 接口新增字段

```json
"warmup": {
  "running": false, "done": 15, "total": 15, "skipped": false,
  "enabled": true,          // 是否启用（HLM_SKIP_WARMUP 的反面）
  "limit": 15,              // 本次预热的数量上限
  "n_questions": 15         // 清单总长度
}
```

> **坑**：第一版禁用时没有设置 `_warmup_state`，
> 导致 stats 里 `skipped=False, reason=''` —— 看不出「是被禁用」还是「没跑」。
> 修法：禁用时也写 state。
