# S21-0 · 设计：AI 自定义查询（让 AI 写代码并运行）

> 日期：2026-10-24
> 需求：「用户向 AI 提问要查询的内容（可以是额外的统计，比如全文中出现了几次"之"字），
>        AI 来编写代码实现查询」

---

## 一、这个功能是什么

```
用户：全文中出现了几次「之」字？
  ↓
AI：写代码（Python）→ 在沙箱里运行 → 读取语料 → 统计 → 返回结果
  ↓
界面：显示代码 + 执行结果 + 耗时
```

**本质是一个「受控代码执行」功能** —— 风险最高的一类功能，必须先解决安全问题。

---

## 二、安全评估（先说风险）

### 2.1 攻击面

| # | 风险 | 后果 |
|:---|:---|:---|
| 1 | `import os; os.system("rm -rf /")` | 删数据 |
| 2 | `open("/etc/passwd").read()` | 读敏感文件 |
| 3 | `socket.connect(...)` 外传数据 | 数据泄露 |
| 4 | `while True: pass` | 耗尽 CPU |
| 5 | `bytearray(10**10)` | 耗尽内存 |
| 6 | `open("x","w").write("...")` × 10000 | 撑爆磁盘 |
| 7 | `subprocess.run("...")` | 执行任意命令 |
| 8 | 死锁 / fork 炸弹 | 拖垮容器 |

### 2.2 可用隔离手段（实测）

在 `hlm-api` 容器内实测结果：

| 手段 | 可用性 | 说明 |
|:---|:---:|:---|
| `timeout` | ✅ | 墙钟超时 |
| `prlimit --cpu` | ✅ | CPU 时间限制 |
| `prlimit --as` | ✅ | 地址空间限制（实测触发 MemoryError） |
| `prlimit --nproc` | ✅ | 进程数限制（防 fork 炸弹） |
| `prlimit --fsize` | ✅ | 单文件大小限制 |
| `unshare --net` | ❌ | **容器无 CAP_SYS_ADMIN** |
| `firejail` / `bwrap` | ❌ | 未安装 |
| `RestrictedPython` | ❌ | 未安装 |

**结论：只能靠「Python 层 AST 白名单 + subprocess 资源限制」双重防护。**

### 2.3 防护策略（五层）

```
第 1 层：AST 静态检查（拒绝危险语法）
   ↓ 拒绝 import os/sys/socket/subprocess、open()、exec()、eval()、__import__ …
第 2 层：受限内建（builtins 白名单）
   只给 len/sum/max/min/sorted/enumerate/range/zip/str/int/float/dict/list/set
第 3 层：数据入口白名单
   只允许通过预设 API 读语料（load_chapter/load_all_text），不允许直接 open()
第 4 层：subprocess 资源限制
   prlimit --cpu=5 --as=512M --nproc=8 --fsize=1M + timeout 10
第 5 层：网络拦截
   在受限 builtins 里移除 socket/urllib/http，并在子进程里 patch socket
```

## 三、方案设计

### 3.1 整体流程

```
用户提问
  ↓
① 判断是否「自定义查询」型问题
   关键词：出现几次 / 统计 / 有多少个 / 频次 / 分布 / 平均 / 最长 / 最短
   或用户显式点击「🔬 自定义查询」按钮
  ↓
② 让 LLM 生成代码（受约束的 prompt）
   给出语料 API 签名 + 输出格式要求 + 安全约束
  ↓
③ AST 静态检查（危险语法直接拒绝，不执行）
  ↓
④ 子进程沙箱执行（prlimit + timeout）
  ↓
⑤ 把「代码 + 结果」交给 LLM 生成自然语言解释
  ↓
⑥ 前端展示：代码块 + 执行结果 + 耗时
```

### 3.2 语料 API（提供给 AI 的接口）

```python
# 只暴露这几个函数，AI 只能通过它们读数据
load_chapter(ver: str, hui: int) -> str
    """读某一回全文。ver ∈ {fuqinju, chenggao, guiyouben}"""

load_all_text(ver: str = "fuqinju") -> str
    """读某版本全部正文（拼接）"""

load_pizhu(ver: str = "fuqinju") -> list[str]
    """读该版本的批语文本列表"""

load_person_roles() -> dict
    """人物身份聚合表"""

load_stats() -> dict
    """统计汇总（词频 / 人物频次 / 批语分布）"""

VERSIONS = ["fuqinju", "chenggao", "guiyouben"]
```

### 3.3 代码生成 prompt

```
你是《红楼梦》语料分析助手。用户想查询一个统计问题，请写 Python 代码实现。

【可用 API】
- load_chapter(ver, hui) -> str      读某一回全文
- load_all_text(ver="fuqinju") -> str  读某版本全书正文
- load_pizhu(ver="fuqinju") -> list[str]  读批语
- load_person_roles() -> dict        人物身份表
- load_stats() -> dict               统计汇总
- VERSIONS                           可用版本列表

【约束】
1. 只能用上面这些 API 读数据，**不能用 open()**（会被拒绝）
2. 不能 import 任何模块（标准库也不行）
3. 不能用 exec/eval/compile
4. 结果必须赋给变量 `result`（可以是 int/float/str/list/dict）
5. 可以 print() 中间调试信息，但最终结果必须在 result 里
6. 代码不超过 40 行

【输出格式】
只输出一个 ```python 代码块，不要任何解释。

【示例】
用户：全文中出现了几次「之」字？
代码：
```python
text = load_all_text("fuqinju")
result = text.count("之")
print(f"全文共 {len(text)} 字")
```
```

### 3.4 AST 检查规则

**禁止的 AST 节点和名字**：

| 类别 | 拒绝内容 |
|:---|:---|
| Import | `Import`, `ImportFrom` 全部拒绝 |
| 危险内建 | `open`, `exec`, `eval`, `compile`, `__import__`, `globals`, `locals`, `vars`, `dir`, `getattr`, `setattr`, `delattr`, `input`, `breakpoint` |
| 危险属性 | `__class__`, `__bases__`, `__subclasses__`, `__globals__`, `__code__`, `__reduce__`, `__builtins__` |
| 文件写入 | 任何 `open(...)` 调用（连读也不允许，用 API） |
| 网络 | `socket`, `urllib`, `http`, `requests`, `ftplib` |
| 进程 | `subprocess`, `os.system`, `os.popen`, `multiprocessing`, `threading` |

### 3.5 执行沙箱

```bash
prlimit \
  --cpu=5 \
  --as=536870912 \
  --nproc=8 \
  --fsize=1048576 \
  --nofile=32 \
  -- timeout 10 python3 /tmp/query_xxx.py
```

- **CPU 5 秒**：计算密集上限
- **内存 512 MB**：够读全书（约 3 MB 文本 + 处理开销）
- **进程 8**：防 fork 炸弹
- **单文件 1 MB**：防写大文件
- **文件描述符 32**：防打开过多
- **墙钟 10 秒**：兜底

### 3.6 前端展示

```
┌──────────────────────────────────────────────┐
│ 🔬 自定义查询                    [收起代码]  │
├──────────────────────────────────────────────┤
│ 生成的代码                                    │
│ ```python                                     │
│ text = load_all_text("fuqinju")               │
│ result = text.count("之")                     │
│ ```                                           │
├──────────────────────────────────────────────┤
│ 执行结果                                      │
│   之 字出现 8,417 次                           │
│   全文 621,812 字，占比 1.35%                  │
│   ⏱ 42 ms                                      │
└──────────────────────────────────────────────┘
```

## 五、我的建议

### 建议做，但必须满足三个前提

1. **AST 白名单 + subprocess 双重隔离** —— 不能只靠一层
2. **必须有安全测试** —— 至少 20 个恶意代码用例，全部验证被拒绝
3. **前端明确标注「这是 AI 生成的代码，已在受限环境执行」** —— 用户知情

### 如果只想快速验证价值

**缩小版（3h）**：
- 不做自由代码生成，改成**模板化查询**
- 预定义 10 种查询模板（字频 / 词频 / 回目统计 / 人物共现…）
- 用户选模板 + 填参数，AI 只负责选模板和解释结果
- **零代码执行风险**

**但这样就失去了「AI 自由写代码」的核心价值。**
