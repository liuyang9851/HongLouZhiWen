### 关键决策：不引入这些库

本项目前端是**纯原生 ESM + 零外部依赖**（`index.html` 只加载本地 js，无任何 CDN）。
引入 Three.js（≈600KB）或 3d-force-graph 会：

- 破坏「离线可用」这一前提（答辩现场断网就白屏）
- 与现有手写 canvas 图表体系（`chart.js` 的 bar/hbar/line/pie/heat/force）风格割裂

所以**只借鉴形式与交互范式，代码全部自写**。3D 用 WebGL 原生 API，2D 用 Canvas 2D。

## 二、新增的三块可视化

### 2.1 3D 力导向图（人物关系页）

`chart3d.js → force3d()`

| 项 | 实现 |
|:---|:---|
| 渲染 | WebGL，点用 `POINTS` + 圆形 alpha 遮罩（片元里 `discard` 圆外像素，做出球感 + 高光） |
| 投影 | 手写 4×4 矩阵：透视投影 × RotX × RotY × Translate |
| 布局 | **确定性分层布局**（非随机力导向）：六家族各占一个方位角，族内按度数由内向外，y 轴按提及频次分层 |
| 大小 | 节点半径 = f(度数)，度数越大越大 |
| 颜色 | 六大家族（绛红/靛蓝/紫/金黄/翠绿/灰） |
| 交互 | 拖拽旋转、滚轮缩放、点击选中（选中后邻居高亮、非邻居降亮） |
| 深度 | 按景深排序后绘制 + 深度雾，远点淡出 |

**为什么不用真力导向**：350 节点要数百帧才收敛，打开先是一团空白。
改成确定性布局后**一打开就有结构**，物理只做轻微松弛（alpha 从 0.35 起快速衰减）。

### 2.2 人物出场曲面（统计页）

`chart3d.js → surface3d()`　数据源 `web/data/person_hui_matrix.json`

**为什么改掉原来的「3D 回目地形」**：逐回字数是一维数据，做成 3D 只是换视角、不增加信息。
换成真正需要三个维度的量：

| 轴 | 含义 |
|:---|:---|
| x | 回目 1–80 |
| y | 人物 Top-30（按全书提及排序） |
| **z（高度）** | 该人物在该回被提及的次数 |

30 × 80 = **2,400 根柱**，颜色按高度分阶（青灰 → 金 → 绛红）。

读出来的结论（全部来自实测矩阵）：

| 现象 | 数据 |
|:---|:---|
| 宝玉戏份最集中的一回 | 第 19 回（117 次） |
| 贾母峰值 | 第 40 回（86 次）——两宴大观园 |
| 王熙凤峰值 | 第 74 回（66 次）——抄检大观园 |
| 黛玉峰值 | 第 3 回（77 次）——进贾府 |
| 人物登场最密集的回 | 第 40 回（371 次）、第 57 回（361 次） |
| **缺席最久的人物** | 柳湘莲缺席 76 回、刘姥姥 74 回、秦钟 69 回 |

「缺席回数」这个维度在原有一维统计里完全看不到——
它揭示了**配角是「事件型出场」而非「常驻」**这一结构特征。

### 2.3 家族和弦图（人物关系页）

`chart3d.js → chord()`

把 674 条人物关系聚合成 **6×6 家族矩阵**，用弦宽表示两家之间的关系的条数：

```
        贾   史   王   薛   林  其他
贾  [  37,   3,   2,   4,   4,  55 ]
史  [   3,   1,   0,   0,   1,  13 ]
王  [   2,   0,   4,   0,   1,   6 ]
薛  [   4,   0,   0,   8,   0,  10 ]
林  [   4,   1,   1,   0,   3,   1 ]
其他[  55,  13,   6,  10,   1,  27 ]
```

读出来的结论：**贾家与「其他」的连接最密（55 条）**，说明贾府人物与府外人物往来最多；
贾史王薛四家之间的两两连接反而不多（3/2/4/4 条）——「四大家族」在关系图上并不紧密。

**同族关系改画内环弧**：原本 i==j 的弦会横跨圆心把整张图糊死，改成外环内侧的同心弧。

## 三、交互设计

人物关系页新增三个视图切换按钮：

```
[ 2D 平面 ]  [ 3D 立体 ]  [ 和弦图 ]
```

切换时**重建 canvas 节点**——因为一个 canvas 一旦取了 `2d` 上下文就再也不能取 `webgl`：

```js
const fresh = cv.cloneNode(false);
cv.parentNode.replaceChild(fresh, cv);
```

WebGL 不可用时自动退回 2D 并提示，不会白屏。

## 四、踩过的坑（都靠数值复算定位）

| # | 现象 | 根因 | 修法 |
|:--|:---|:---|:---|
| 1 | 3D 图一片空白 | `gl_PointSize = a_size / clip.w * 260`，视距 1247 时只有 1.2 像素 | 引入 `u_scale`（画布高度推导），并钳制 `[2.5, 64]` 像素 |
| 2 | 3D 图整体偏到右上角 | **矩阵乘法顺序错**：`mat4Mul(view, mat4Translate(...))` 使平移也被旋转 | 改成 `Translate * RotX * RotY`（最左最先作用） |
| 3 | 3D 图缩成一小团 | autoFit 只在 90 帧内生效，之后 R 继续缩小但视距不跟 | 改为持续跟随包围球 |
| 4 | 视距算不准 | 用 `aspect` 修正没用，因为纵向是固定比例溢出 | 按**垂直半视角**推导：`dist = r / sin(fov/2) × 1.05` |
| 5 | 曲面图柱体过大遮住网格 | 柱宽 0.62、高度系数 1.9 过大 | 收细到 0.42、压低到 1.35，相机拉远到 zoom 0.74 |
| 6 | 曲面图标签重叠 | 人物轴每 NY/8 标一个，30 人时过密 | 改为每 NY/6 且字号降到 9px |
| 7 | 和弦图空白 | `ReferenceError: chord is not defined` —— import 只加了 `force3d` | 补进 import 列表 |
| 8 | 和弦图中心糊死 | 同族弦横跨圆心 | 改画内环弧 + 中心留白圆 |

**坑 2 的教训**：矩阵乘法顺序是最容易错又最难肉眼发现问题的地方。
我用「球心 (0,0,0) 变换后应为 (0,0,-dist)」做了单元测试，一测就发现球心跑到了 (673,-328,-927)。

## 七、未做的事（如实说明）

1. **没有引入真力导向**：确定性布局更稳，但少了「力导向自组织」的观感；如需可加开关
