## 一、首屏背景插画

### 1.1 素材

| 项 | 值 |
|:---|:---|
| 文件 | `web/public/img/hero-bg.png` |
| 大小 | 493 KB（1920×约1200，红楼梦大观园工笔插画）|
| 说明 | 附件原名后缀是 `.jpg`，但文件头是 `89 50 4E 47`（PNG），已按真实格式命名 |

### 1.2 范围：仅第一面

```css
.hp-hero {
  /* 铺满首屏：视口高 − 顶栏 − 页面上下内边距 */
  min-height: calc(100vh - var(--topbar-h) - 108px);
  overflow: hidden;
  border-radius: 14px;
}
```

`.hp-hero` 是欢迎页第一个区块（包含印章、主标题、副标题、导语、KPI 卡、CTA 按钮），
高度撑到首屏，**第二个区块「关于《红楼梦》」开始就是纯色背景**。

### 1.3 渐变：从上到下过渡到纯色

双层背景（上层蒙版 + 下层插画）：

```css
background-image:
  linear-gradient(
    to bottom,
    rgba(250,247,242,.55)  0%,    /* 顶部：压一层纸色，标题可读 */
    rgba(250,247,242,.40) 28%,
    rgba(250,247,242,.62) 60%,
    rgba(250,247,242,.88) 85%,
    var(--paper)         100%     /* 底部：完全过渡到纯色 */
  ),
  url('/img/hero-bg.png');
background-size: cover, cover;
background-position: center top, center top;
```

**关键点**：最后一档是 `var(--paper)`（不透明），所以底部与下方区块**完全同色**，
不会出现硬边。再叠一层 `::after` 做 120px 的柔和收尾：

```css
.hp-hero::after {
  content: '';
  position: absolute; left: 0; right: 0; bottom: 0; height: 120px;
  background: linear-gradient(to bottom, rgba(250,247,242,0), var(--paper) 88%);
  pointer-events: none;
}
```

### 1.4 文字可读性

插画是工笔重彩，直接压黑字会糊。方案是**三层保障**：

| 层 | 做法 |
|:---|:---|
| 1 | 上方渐变蒙版（顶部就压到 55% 不透明）|
| 2 | `.hp-hero-inner` 叠一层径向纸色光晕：中间清晰、四周让插画透出 |
| 3 | 标题/副标题加纸色 `text-shadow` |

```css
.hp-hero-inner {
  padding: 8px 26px;
  border-radius: 18px;
  background: radial-gradient(
    ellipse 78% 68% at 50% 46%,
    rgba(250,247,242,.88) 0%,
    rgba(250,247,242,.70) 55%,
    rgba(250,247,242,0) 100%);
}
.hp-hero .hp-title { text-shadow: 0 2px 10px rgba(250,247,242,.95); }
.hp-hero .hp-sub,
.hp-hero .hp-lead { color: var(--ink-2); text-shadow: 0 1px 2px rgba(250,247,242,.9); }
```

### 1.5 效果

首屏：插画在四周和顶部清晰可见，中间文字区被纸色光晕托住，KPI 白色卡片压在插画上仍然清楚。
向下滚动：渐变收束成纯色，与「关于《红楼梦》」区块无缝衔接。

## 二、背景音乐：为什么不用 `<audio>`

### 2.1 技术约束

| 方案 | 问题 |
|:---|:---|
| `<audio src="x.m4s" loop>` | `.m4s` 是 **fragmented MP4 分片**，浏览器 `<audio>` 对单分片的 seek/loop 不可靠，且无法保证从 0 完整播放 |
| 转码成 mp3/ogg | 需要额外工具链，且改变了原始素材 |
| **外部播放器 mpv.net** | ✅ 原生支持 `.m4s`，`--loop-file=inf` 精确循环 |

所以采用：**页面 → 本地 Node 服务 → 拉起 mpv.net**。

### 2.2 服务端接口

`web/server.js` 新增三个接口：

| 接口 | 作用 |
|:---|:---|
| `POST /api/bgm/start` | 启动播放（**幂等**：已在播则返回 `already:true`）|
| `POST /api/bgm/stop` | 停止播放 |
| `GET /api/bgm/status` | 查询状态 `{playing, pid, file, player}` |

配置项（均可用环境变量覆盖，不硬编码）：

```javascript
const BGM_FILE   = process.env.HLM_BGM_FILE   || 'D:\\Download\\774293639-1-30280.m4s';
const BGM_PLAYER = process.env.HLM_BGM_PLAYER || 'D:\\mpv.net\\mpvnet.exe';
```

播放参数：

```javascript
spawn(BGM_PLAYER, [
  '--loop-file=inf',     // 单曲循环
  '--no-video',          // 只要音频（.m4s 可能含视频流）
  '--force-window=no',   // 不弹播放器窗口
  '--no-terminal',
  '--really-quiet',
  '--volume=70',
  BGM_FILE,
], { detached: true, stdio: 'ignore', windowsHide: true });
```

### 2.3 三个关键设计

**① `detached: true` + `unref()`**

普通子进程会随 Node 服务退出而终止，导致「重启前端服务 → 音乐停了」。
改成独立进程后，服务重启不影响播放。

**② PID 持久化到 `web/data/.bgm.pid`**

服务重启后内存里的 `bgmProc` 丢失，原本会误判为「未播放」，进而重复拉起第二个 mpv。
现在把 PID 落盘，重启后仍能识别在播进程：

```javascript
function currentBgmPid() {
  if (bgmProc && bgmProc.exitCode === null) return bgmProc.pid;
  const pid = readBgmPid();            // 读 PID 文件
  return pidAlive(pid) ? pid : null;   // process.kill(pid, 0) 探活
}
```

`stop` 也据此兼容：服务重启过也能按 PID 结束进程。

**③ 幂等**

```
第一次 start → {ok:true, already:false, pid:19576}
第二次 start → {ok:true, already:true,  pid:19576}   ← 不会起第二个进程
```

### 2.4 前端触发

`app.js` 的 `initBgm()` 在 `boot()` 里调用，**每次打开页面都确保在播**：

```javascript
api('/api/bgm/start').then((d) => { if (!d.ok) console.warn(...) });
```

不加 `sessionStorage` 门槛 —— 因为 start 本身幂等，重复调用无副作用，
这样才能做到「打开网页就播」。

### 2.5 静音开关

顶栏右侧新增 🔊 / 🔇 按钮：

- 点击切换播放 / 停止
- 图标与 `active` 高亮反映真实状态
- 页面加载时从 `/api/bgm/status` 同步一次

## 三、顺带修复：顶栏换行

加了音频按钮后顶栏超宽，出现「红楼智/问」「配/置」折行。

| 问题 | 修法 |
|:---|:---|
| 品牌名折行 | `.brand { flex: none }` + `.brand-text { white-space: nowrap }` |
| 右侧无法收缩 | `.topbar-right { min-width: 0; flex: 0 1 auto; gap: 12px→10px }` |
| 状态胶囊过长 | `.status-pill { white-space: nowrap; overflow: hidden; min-width: 0 }` |
| 模型名被截 | `.model-picker select { max-width: 300px→268px }`（再小会切掉下拉箭头）|

## 六、如果是别的机器部署

两个路径是本机绝对的，换机器需要改环境变量：

```bash
HLM_BGM_PLAYER="C:\path\to\mpvnet.exe"
HLM_BGM_FILE="D:\path\to\bgm.m4s"
node server.js
```

或者直接把音频转成 `.mp3` 放到 `web/public/audio/`，改用 `<audio loop>` 播放
（适合不支持外部播放器的场景，但需先转码）。

## 七、教训

| # | 教训 |
|:---|:---|
| 1 | **文件扩展名不可信**。附件叫 `.jpg`，实际是 PNG（文件头校验才发现）。 |
| 2 | **子进程要 detached**。否则宿主服务一重启，音乐就断。 |
| 3 | **进程状态要落盘**。Node 内存里的 PID 在重启后是空的，必须写文件才能在重启后正确停止/判重。 |
| 4 | **加一个顶栏按钮就要复查顶栏是否还放得下**。这次加了 50px 就折行了。 |
| 5 | **背景图上放文字必须有蒙版**。只靠阴影不够，工笔画细节太多。 |
