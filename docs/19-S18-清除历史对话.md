## 二、关键设计

### 2.1 明确「删什么 / 不删什么」

用户最担心的是「点了会不会把别的东西也删了」。弹窗里直接列清楚：

| | 内容 |
|:---|:---|
| ✅ 删除 | 对话列表与消息内容（localStorage hlm:sessions） |
| ❌ 保留 | 语料、索引、向量、模型配置、阅读进度 |

### 2.2 二次确认 + 显示影响范围

- 显示「将删除 **N** 个对话（共 **M** 条消息）」—— 让用户知道影响多大
- 红字「此操作不可撤销」
- 三个退出路径：取消按钮 / 点遮罩 / ESC 键

### 2.3 顺带清理「阅读进度」

`javascript
// 一并清掉各版本的「上次阅读回次」
Object.keys(localStorage)
  .filter((k) => k.startsWith('hlm:lastHui:'))
  .forEach((k) => localStorage.removeItem(k));
`

这属于「历史痕迹」，清空对话时一并清掉更彻底。
（但弹窗里「保留」清单写的是「阅读进度」—— **这里有表述不一致**，
见下方「已知问题」。）

### 2.4 清除后不留空白

`javascript
state.sessions.unshift({
  id: Date.now(), title: '红楼梦问答', time: Date.now(), msgs: [],
});
`

如果清成 0 条，界面会没有任何会话可选，用户会以为坏了。
