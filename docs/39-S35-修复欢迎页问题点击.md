# S35 · 修复欢迎页「试试这些问题」点击不生效

> 日期：2026-10-26
> 反馈：「欢迎页里的『试试这些问题』里的问题，点击后跳转没有真正输入问题并发送 AI」

---

## 一、现象

点击欢迎页第 5 节的任一问题卡片：
- ✅ 会跳转到 AI 问答页
- ❌ 输入框是空的
- ❌ 没有触发提问

---

## 二、根因

`page_home.js` 第 360 行用了 `$(...)`：

```js
const ta = $('#chatTextarea');   // ← $ 未定义
```

但 `page_home.js` 是**独立模块**，它只从 `window.__HLM__` 取了这几个：

```js
const H = () => window.__HLM__ || {};
const esc = (s) => { ... };
const api = (p) => H().api(p);
const getStarters = () => H().STARTERS || [];
const autoGrowFn = () => window.__HLM__ && window.__HLM__.autoGrow;
const sendFn = () => window.__HLM__ && window.__HLM__.send;
```

**`$` 从来没被导入过。** `app.js` 里虽然定义了 `const $ = (s, r = document) => r.querySelector(s);`，
但它是模块作用域的私有变量，没挂到 `window.__HLM__` 上。

结果：`onclick` 一执行就抛 `ReferenceError: $ is not defined`，
后面的 `ta.value = ...` 和 `send()` 全部没跑到。

**为什么之前看不出问题**：`onclick` 里的异常不会中断页面渲染，只是静默失败——
页面正常跳到问答页，只是输入框空着，看起来像"点了没反应"。

---

## 三、修法

### 3.1 把 `$` 暴露出去

`app.js` 的 `window.__HLM__` 增加一项：

```js
window.__HLM__ = {
  esc, el, api, $,          // ← 新增 $
  ...
};
```

### 3.2 点击处理改为「延迟取 + 重试」

原实现只 `setTimeout(..., 260)` 等一次，赌路由渲染时机。
改成轮询重试，最多 12 次（约 1.2 秒）：

```js
b.onclick = () => {
  const q = b.dataset.q || '';
  location.hash = '#/chat';

  let tries = 0;
  const trySend = () => {
    const H = window.__HLM__ || {};
    const $ = H.$;
    // $ 拿不到就退回原生 API，保证一定取到元素
    const ta = $ ? $('#chatTextarea') : document.querySelector('#chatTextarea');
    const autoGrow = H.autoGrow;
    const send = H.send;

    if (!ta || !send) {
      if (++tries < 12) return setTimeout(trySend, 100);
      console.warn('[home] 无法进入问答框，放弃自动发送');
      return;
    }
    ta.value = q;
    if (typeof autoGrow === 'function') autoGrow(ta);
    ta.dispatchEvent(new Event('input', { bubbles: true }));   // 触发监听器
    try { send(); } catch (e) { console.warn('[home] 自动发送失败:', e); }
  };
  setTimeout(trySend, 60);
};
```

三处改进：
1. **不再依赖时序**：轮询到元素就绪为止
2. **有兜底**：`$` 取不到时直接用 `document.querySelector`
3. **补发 input 事件**：有些逻辑监听 `input` 而不是只读 `.value`

## 六、教训

**跨模块协作不能靠"隐式全局"。**

`app.js` 里 `$`、`autoGrow`、`send` 都是模块作用域的函数，`page_home.js` 是另一个模块。
之前有人写了 `$('#chatTextarea')` 却没检查 `$` 是否可见——JavaScript 不会在加载时报错，
只在**用户点击那一刻**才抛异常，而且异常被 `onclick` 吞掉，表现成"点了没反应"。

这类问题的特征是：**页面看起来正常，但某个交互静默失效**。
排查方法就是打开控制台看有没有 `ReferenceError`——一眼就能定位。

另外，原代码用固定 `setTimeout(260)` 等路由渲染，本身就是脆弱的写法：
机器慢一点就失败。改成轮询重试才是稳的。
