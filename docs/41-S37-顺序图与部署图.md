# S37 · 程序架构改为三段递进：顺序图 → 完整架构 → 部署图

> 日期：2026-10-27
> 需求：原架构图太复杂，先要一个简单图给同学建立直观印象（顺序图/通信图），再补一个部署图

---

## 一、为什么改

原来的「2 程序架构」只有一张组件级架构图，信息密度太高：
第一次看的人容易陷进 HDFS / HBase / Spark / Flink 这些名词里，**抓不住"一次提问到底发生了什么"**。

改成 **三段递进**：

```
① 顺序图   一次提问经历了什么          ← 先建立直观印象
② 完整架构  同样的流程，展开到组件级     ← 原图保留
③ 部署图   这些东西都跑在哪            ← 落到物理/容器视图
```

一句话概括三张图的分工：

| 图 | 回答的问题 | 抽象层次 |
|:---|:---|:---|
| 顺序图 | **怎么跑的**（时间维度）| 4 个参与者 |
| 架构图 | **由什么组成**（结构维度）| 20+ 组件 |
| 部署图 | **跑在哪**（物理维度）| 进程 / 容器 / 云 |

## 二、顺序图（UML Sequence Diagram）

![顺序图](../../docs/shots/66-sequence-standalone.png)

### 2.1 结构

**4 条生命线**（按信息流方向排列）：

```
用户/浏览器  →  FastAPI 后端  →  HBase 索引  →  DeepSeek
```

**左侧 4 个阶段栏**（帮助第一次看的人抓住主线）：

```
① 检索    提问 + 三路召回 + 候选片段
② 融合    RRF 融合 + 同回去重
③ 生成    拼 prompt + 流式 token
④ 展示    SSE 推送 + 打字机 + 跳转原文
```

### 2.2 消息序列（8 条）

| # | 消息 | 方向 |
|:--|:---|:---|
| ① | 提问「宝玉和黛玉什么关系？」 | 浏览器 → 后端 |
| ② | 三路召回：关键词 + 向量 + 图谱 | 后端 → HBase |
| ③ | 候选片段 Top-30 | HBase → 后端（虚线返回）|
| ④ | RRF 融合 k=60 + 同回去重 | 后端自调用 |
| ⑤ | 拼装 prompt（片段 + 引用编号）| 后端 → DeepSeek |
| ⑥ | 流式返回 token | DeepSeek → 后端（虚线）|
| ⑦ | SSE 推送增量 + citations | 后端 → 浏览器（虚线）|
| ⑧ | 打字机显示，引用角标可点击 / 点击跳转原文 | 浏览器自调用 |

### 2.3 实现要点

**自调用用回折箭头**（不是普通直线）：

```javascript
const selfMsg = (x, y, label, color, marker, w = 46, h = 34) => `
  <path d="M ${x} ${y} h ${w} v ${h} h ${-w}" fill="none" stroke="${color}"
        stroke-width="1.9" marker-end="url(#${marker})"/>
  ${txt(x + w + 10, y + h / 2 + 5, label, 13.5, C.text, 600, 'start')}`;
```

**阶段栏用旋转文字** `transform="rotate(-90 x y)"`，写成竖直标签，不占横向空间。

**虚线 = 返回消息**，实线 = 调用消息 —— UML 惯例。

### 3.2 连线与标注

| 连接 | 标注 |
|:---|:---|
| 浏览器 → Node | HTTP |
| Node → hlm-api | proxy /api/* |
| hlm-api → DeepSeek | HTTPS |
| hlm-api → Docker 集群 | Thrift 9090 |
| Node → 本地磁盘 | Range 流式读（虚线）|
| Node → mpv.net | 启动播放 |

## 四、实现与验证方法

### 4.1 文件结构

```
web/public/js/diagrams_simple.js     ← 新增，两张图（零依赖 SVG）
  export renderSequenceDiagram()
  export renderDeploymentDiagram()
web/public/js/page_home.js           ← 第 2 节接入
web/public/css/pages.css             ← .hp-diagram-wrap / .hp-diagram-tip
```

### 4.2 验证方法：脱离 SPA 单独渲染

浏览器自动化调试时遇到一个障碍：**SPA 路由会干扰**，
导航到独立的测试 HTML 时页面会被拉回 `#/graph`，截不到图。

解决办法：写 `scripts/s37_render_diagrams.mjs`，
用 Node 直接 import 模块、把 SVG 渲染成独立 HTML：

```bash
node scripts/s37_render_diagrams.mjs
# 产出 web/public/_seq_diagram.html / _dep_diagram.html
```

独立 HTML 不含 SPA 外壳，浏览器可以正常加载 → 截图检查。

脚本同时做**结构自检**：

```
seq: <svg>=1 </svg>=1 OK
dep: <svg>=1 </svg>=1 OK
（并检查是否含 undefined / NaN）
```

> 这个脚本保留在仓库里，以后改图可以直接跑它做快速预览。

### 4.3 排版踩的坑

第一版部署图有 4 类问题，全部修掉：

| 问题 | 原因 | 修法 |
|:---|:---|:---|
| 文字溢出方框 | 框高按固定值给，条目多了就溢出 | 高度按条目数推算：`h ≥ 78 + n*22 + 26` |
| 连线压住文字标签 | 标签放在线中点，线又穿过框 | 标签统一放到线上方 8-9px；折线绕开中间模块 |
| 底部注释与容器边框重叠 | 注释 y 与容器下边框几乎重合 | 画布加高 820→880，集群下移，注释移到 806 |
| `proxy /api/*` 压住目标框 | 两个框间距 62 单位，标签要 90 单位 | hlm-api 右移 40，间距 102 |
