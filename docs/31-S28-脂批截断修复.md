# S28 · 修复脂批截断

> 日期：2026-10-25
> 反馈：「我发现这里仍有脂批被截断的问题，你能修复一下吗？」（附原文阅读界面截图）

---

## 一、问题现状

截图右侧「脂批」栏里，多条批语在句子中间被切断：

| # | 显示内容（尾部） | 判断 |
|:--|:---|:---|
| 1 | 「…负师友规谈之德，**以至今**」 | 断在「以至今日」中间 |
| 2 | 「…万不可因我之不肖，自护己短，**一**」 | 断在「一并使其泯灭也」中间 |
| 3 | 「…是提醒阅」 | 断在「阅读者眼目」中间 |

这不是显示层截断，是**数据本身就是断的**。

---

## 二、根因：判据用错了

### 2.1 旧脚本的判据

`pipeline/s10_1_unify_pizhu.py` / `s12_1_fix_pizhu_truncation.py` 用
**「字体名是不是楷体」** 来区分批语和正文：

```python
def is_kai(bf):
    return ('KaiTi' in bf) or ('SimHei' in bf)
```

### 2.2 为什么错

实测这套 PDF 的排版（逐 span 取字体 + 字号）：

| 内容 | 字号 | 字体 |
|:---|:---:|:---|
| 正文 | **22.9** | SimSun |
| 行内脂批 | **19.1** | KaiTi_GB2312 |
| 批语起始 ◆ | 19.2 | EUDC（\ue04f 等） |
| 回前/回末批（总评） | **22.9** | KaiTi_GB2312 |
| 现代编者校注 | **19.1** | **SimSun** |
| 页眉 | 17.2 | — |
| 校注圈号 ① | 11.5 | SimSun |

**关键问题在第 22–23 页的凡例**：凡例整段也用楷体印刷。

于是旧脚本把「凡例正文 + 夹在里面的脂批」当成**一条大批语**，
一路收到页末 `flush()`，就断在页边界：

```
第 22 页末：…负师友规谈之德，以至今   ← 收批语到页末，停在这里
第 23 页首：日一技无成、半生潦倒之罪，  ← 这半句丢了
```

**正确的判据是字号**（批语恒 19.1，正文恒 22.9），不是字体名。

### 2.3 第二个坑：显示层又截一次

`s16_build_pizhu_by_version.py` 第 89/128 行：

```python
'text': (r.get('text') or '')[:300],   # 写前端时再硬截 300 字
```

即使数据是完整的，超过 300 字的批语到界面也会被切，且**没有省略号**。

---

## 三、修法

### 3.1 重写提取（`s28_4_reextract_pizhu_v4.py`）

| 规则 | 作用 |
|:---|:---|
| 只收 **18.5–19.6 号** KaiTi span | 行内脂批（排除同字号的 SimSun 校注） |
| **正文一出现就结束批语** | 这是修截断的核心——批语不会跨页失控累积 |
| 跨页不 flush，下一页接着收 | 批语真正跨页时能连上 |
| 圈号 ①–⑳ 出现即结束并跳过 | 剔掉现代编者校注（19.1 号 SimSun，非脂批） |
| **22.9 号 EUDC 标记 → 回前/回末批**（总评） | 补回原先完全丢失的「总评」类批语 |
| 22.9 号无标记楷体 → 按正文 | 排除凡例正文 |
| 整段以「此开卷第一回也」开头 → 丢弃 | 那是凡例第五条，不是脂批 |
| 回次按**页眉**（y<95、17.2 号、含「第N回」）锚定 | 旧法用「本页第一个第N回」，会被正文里的「第N回」误导，导致 5 个回次丢失 |

### 3.2 保留版本归属

批语的版本标签（甲戌本／庚辰本／戚序本…）来自 PDF 里的 **EUDC 标记码**：

| 码 | 版本 | 码 | 版本 |
|:---|:---|:---|:---|
| \ue04f | 甲戌本 | \ue054 | 蒙府本 |
| \ue051 | 己卯本 | \ue055 | 列藏本 |
| \ue052 | 庚辰本 | \ue056 | 杨藏本 |
| \ue053 | 戚序本 | \ue057 | 甲辰本 |

（从旧数据 3234 条单字符 code 统计得出，100% 唯一对应）

新提取逐条记录标记码 → 映射回 `versions_legend`，**标签没有丢**。

### 3.3 去掉显示层 `[:300]`

`s16_build_pizhu_by_version.py` 与 `build_ui_data.py` 的 `[:300]` 全部删除。

### 3.4 放开每回条数上限

`MAX_PER_HUI = 30` → `250`。

原因：数据修好后第 1 回有 224 条批语，但侧栏只显示 30 条 ——
**修好的大部分数据根本看不到**。

## 五、剩余问题（如实说明）

### 5.1 仍有 107 条（2.3%）疑似截断

多为批语在页内被**字体切换**打断（如引文换了字体），或极端排版。
典型样本：

```
'谚云：'                       ← 后面引文换了字体
'惯用险笔如'                    ← 同上
'限门盆魂痕昏'                  ← 咏菊限韵字，可能是完整枚举
```

这批属于个案，需要逐条对照 PDF 处理，收益递减。

### 5.2 RAG 索引仍是旧数据

**本次只修了阅读界面的展示数据**（`web/data/versions/*/chapter_*.json`）。

HBase 里的 8,510 条脂批 chunk（`hlm_chunks` / `hlm_vectors` / `hlm_terms`）
仍来自旧的截断文本，所以**AI 回答里引用脂批时，引到的仍是旧文本**。

要彻底修复需要重跑脂批索引链路（重新切块 → 重新向量化 → 重写三张 HBase 表 + HDFS）。

## 七、一句话总结

> 截断的根因不是「数据少」，而是**判据选错了维度**：
> 旧代码用「字体名」找批语，但凡例整段也是楷体，于是一条批语吞掉整页、断在页边界。
> 改用「字号」（批语 19.1 / 正文 22.9）后，截断从 35.9% 降到 2.3%，总字数多恢复 66%。
